# Cortex Ship — Push Code and Open PR

Ships validated code to GitHub: creates a feature branch (if needed), pushes, opens a PR with a structured description generated by GSD, and writes the PR state back to Cortex continuity files. This is the last mile between "validators pass" and "code is reviewable on GitHub."

## User-invocable

When the user types `/cortex-ship`, run this skill.
Also trigger when: "ship this", "open a PR", "push and PR", "ship the slug", "create pull request".

## Arguments

- `/cortex-ship` — ship the current active slug (no arguments required)
- `--issue <N>` — link PR to GitHub issue #N (adds "Closes #N" to PR body)
- `--draft` — open as draft PR instead of ready for review
- `--dry-run` — show what would happen without pushing or creating PR

## Instructions

### Phase 1: Guard Checks

All guards must pass. If any fail, stop with the error message.

1. **Slug exists:** Read `.cortex/state.json`. If `slug` is null: "No active slug. Nothing to ship."
2. **Validators passed:** Check that mode is beyond `execute` (assure or later). If mode is still `execute` or earlier: "Validators haven't run yet. Complete execution and validation before shipping."
3. **Clean working tree:** Run `git status --porcelain`. If output is non-empty: "Working tree is dirty. Commit or stash changes before shipping."
4. **GitHub remote exists:** Run `gh repo view --json name 2>/dev/null`. If exit code non-zero: "No GitHub remote found. Skipping ship — run /cortex-close instead."
5. **gh authenticated:** Run `gh auth status 2>/dev/null`. If exit code non-zero: "gh CLI not authenticated. Run `gh auth login` first."
6. **Not already shipped:** Check `state.json` for `github.pr_url`. If already set: "PR already opened at {url}. Use `gh pr view {number}` to check status."

### Phase 2: Branch Management

1. **Check current branch:** Run `git branch --show-current`.
2. **If on main/master:** The work needs a feature branch.
   - Run `/gsd:pr-branch` to create a clean PR branch that filters .planning/ commits.
   - The branch name will be `{current-branch}-pr` or similar per GSD convention.
   - Switch to the PR branch.
3. **If already on a feature branch (cortex/{slug} or other):** Verify it's ahead of main: `git log main..HEAD --oneline`. If no commits ahead: "Branch has no new commits. Nothing to ship."

### Phase 3: Push and Open PR

1. **Push branch:** `git push -u origin HEAD`
2. **Delegate to /gsd:ship:** Invoke `/gsd:ship` which handles:
   - Generating the PR body from GSD artifacts (SUMMARY.md, VERIFICATION.md, ROADMAP.md)
   - Running `gh pr create` with the generated body
   - Updating `.planning/STATE.md`
3. **If /gsd:ship is not available** (GSD not installed or artifacts missing), fall back to manual PR creation:
   ```bash
   gh pr create \
     --title "feat({slug}): {spec_objective}" \
     --body "$(cat <<'EOF'
   ## Summary
   {objective from spec or contract}

   ## Changes
   {deliverables from contract}

   ## Test Plan
   {validators from contract}

   {issue_link}

   Generated by Cortex /cortex-ship
   EOF
   )" \
     --base main
   ```
4. **Capture PR URL and number:** Parse the output of `gh pr create` (prints URL on stdout). Extract PR number from URL.

### Phase 4: Link Issue (if --issue provided)

If `--issue N` was passed:
1. Add "Closes #N" to the PR body (gh pr create supports this via body text).
2. Write `issue_number: N` to state.json.

### Phase 5: Update State

Write to `.cortex/state.json`:
```json
{
  "github": {
    "pr_number": {N},
    "pr_url": "{url}",
    "issue_number": {N or null},
    "branch": "{branch_name}"
  }
}
```

Set gates:
- `gates.pr_opened = true`
- `gates.pr_merged = false`

Append to `docs/cortex/handoffs/decisions.md`:
```
- {ISO8601} | ship | PR #{N} opened for slug {slug} | {url}
```

Update `docs/cortex/handoffs/current-state.md`:
- `next_action`: "PR #{N} open. Poll CI with `gh pr checks {N}`. Merge when ready."

### Phase 6: Output Summary

```
SHIPPED
════════════════════════════════════════
Slug:     {slug}
Branch:   {branch}
PR:       #{number} — {url}
CI:       pending (poll with: gh pr checks {number})
Issue:    {#N or (none)}

Next: cortex-drive will poll CI status automatically.
      Human merges when CI passes.
════════════════════════════════════════
```

## Rules

- Does NOT auto-merge. Merge is always a human decision.
- Does NOT block on CI. Opens the PR and returns. CI polling is handled by cortex-drive rows 10b-10d.
- Does NOT modify .planning/ artifacts directly — delegates to /gsd:ship which owns that.
- Idempotent on re-run: if PR is already open (state.json has pr_url), reports existing PR instead of creating a duplicate.
- If --dry-run is passed, print what would happen and exit without side effects.
