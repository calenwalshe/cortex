# Plan 08-01: Write Discovery Loop Design Doc and Two Artifact Templates

## Objective

Write the three authoritative deliverables for Phase 8 so that all subsequent implementation phases have a concrete schema to implement against:

1. `docs/DISCOVERY_LOOP.md` — design reference covering all 6 required sections
2. `templates/cortex/learning-contract.md` — 12-field template (HDD/Lean Startup/Shape Up synthesis)
3. `templates/cortex/experiment-result.md` — close artifact with 7 required fields

All content is derived from the approved contract (`docs/cortex/contracts/cortex-discovery-loop/contract-001.md`) and spec (`docs/cortex/specs/cortex-discovery-loop/spec.md`). No new semantics are introduced.

## Must Haves

**DISCOVERY_LOOP.md (DISC-01)**
- Section 1: Mode Transitions — valid modes listed (clarify, research, experiment, spec, execute, validate, repair, assure); all transition triggers documented with the state fields that drive them (`reclarify_required`, `experiment_complete`); pre-spec backtracking is permitted; post-spec repair re-enters validate, never clarify
- Section 2: Artifact Schemas — learning-contract and experiment-result schemas documented inline; file paths documented (`docs/cortex/experiments/{slug}/`); lifecycle events that write each artifact documented (open → learning-contract; close → experiment-result)
- Section 3: Uncertainty Register Schema — five fields documented per entry: `type` (frame|knowledge|design|evidence|eval), `severity` (critical|noncritical), `resolution_path` (research|experiment|human), `status` (open|resolved|deferred|accepted-risk), `resolved_by` (pointer); backward-compatibility defaults for flat entries documented
- Section 4: Spec-Readiness Gate — three new blockers documented: (1) `reclarify_required` is false, (2) no critical+open uncertainty entries, (3) all core assumptions backed by evidence; `experiment_complete` gate documented as conditional (only checked if critical uncertainties had `resolution_path: experiment`); state.json schema extensions documented inline
- Section 5: Write-Root Policy — `docs/cortex/experiments/` added to permitted write roots during experiment mode; phase guard and scaffold patches referenced; product-path write guard remains intact
- Section 6: Convergence Guardrails — six guardrails documented: fixed timebox/appetite, learning threshold, specific testable hypothesis, minimal viable experiment, defined decision rule outcomes (promote/iterate/re-clarify/abandon), WIP limit (warn at >1 active contract per slug)

**learning-contract.md template (DISC-02)**
- YAML front matter for header metadata: id, status, owner, slug, created
- 11 Markdown body sections (one per remaining field): Problem Statement, Core Hypothesis, Key Assumptions, Target Context, Experiment Design, Key Metrics / Evidence, Learning Threshold, Risks & Dependencies, Appetite / Timebox, Expected Learning
- `Appetite / Timebox` field marked `<!-- REQUIRED -->` — contract is incomplete without it
- Separate `## Results` section as post-experiment block with placeholder prompts for: Actual Outcomes, Validated Learning, Decision, Rationale, Next Steps
- Decision field includes inline comment listing the four valid values: `promote | iterate | re-clarify | abandon`
- Pre-experiment and post-experiment portions are visually distinct (separate sections)

**experiment-result.md template (DISC-03)**
- 7 fields: Experiment ID, Hypothesis Tested, Actual Outcomes, Validated Learning, Decision, Rationale, Next Steps
- `Linked Contract` field included (path to the learning-contract this result closes)
- Decision field includes inline comment listing four valid values: `promote | iterate | re-clarify | abandon`
- Template is short and focused — this is a close artifact, not a planning artifact
