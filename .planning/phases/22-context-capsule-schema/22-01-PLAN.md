# Phase 22 Plan 01: Context Capsule Template and Result Schema

## Objective

Create the context capsule template (`templates/cortex/task-capsule.md`) and JSON result schema (`schemas/task-result.schema.json`) that enable structured Codex execution handoff. These two files define the contract between the task router (Phase 21) and the Codex execution wrapper.

## Context

- @docs/cortex/research/token-efficiency/implementation-20260402T225932Z.md Section C (capsule format + result schema design)
- @scripts/cortex/task-router.js (upstream consumer — classifies tasks, generates capsules from this template)
- @templates/cortex/gsd-handoff.md (existing handoff template convention)

## Tasks

<task id="1" type="auto">
<name>Create task-capsule.md template</name>
<action>
Create `templates/cortex/task-capsule.md` with all 6 sections specified in the research dossier:

Target size: 3-15KB when populated (template itself ~2KB).
</action>

<task id="2" type="auto">
<name>Create task-result.schema.json</name>
<action>
Create `schemas/task-result.schema.json` as a valid JSON Schema (draft 2020-12) with all fields from the research dossier:
- `status`: enum ["complete", "failed", "checkpoint"] (required)
- `files_changed`: array of strings (required)
- `tests_passed`: boolean (required)
- `test_output_summary`: string (optional)
- `deviations`: array of strings (required, can be empty)
- `commit_hash`: string or null (required)
- `error_message`: string or null (required)
- `checkpoint_detail`: string or null (required)

Schema must be self-contained (no $ref to external files).
</action>

<done>Valid JSON Schema file exists with all 7 required properties and correct types</done>
