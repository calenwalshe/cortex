# Plan 01-02: Rubric YAML + Discriminability Check

## Objective

Write `docs/cortex/rubrics/communication-judge-loop/drive-summary.yaml` with the 5-dimension rubric and run a discriminability check against 10 historical drive summaries to validate the rubric separates good from poor messages.

## Execution Context

- Rubric target path: `docs/cortex/rubrics/communication-judge-loop/drive-summary.yaml`
- Discriminability check: run `judge_communication()` on 10 sample messages (crafted, not real API — mocked judge or real if ANTHROPIC_API_KEY available); confirm rubric produces both PASS and FAIL verdicts
- Discriminability output: `docs/cortex/evals/communication-judge-loop/discriminability-check.md`

## Context

### Rubric structure (from decisions)

The rubric must be YAML-parseable by `judge_communication()`. Structure locked in CONTEXT.md:
```yaml
rubric: drive-summary
version: 1
surface: drive_completion_summary
dimensions:
  - name: clarity
    description: "Single reading comprehension; no ambiguous referents"
    threshold: 3
    scale: 4
  - name: actionability
    description: "Owner can derive next step without follow-up question"
    threshold: 3
    scale: 4
  - name: evidence_traceability
    description: "Every claim references a specific artifact or finding"
    threshold: 2
    scale: 4
  - name: completeness
    description: "All 3 formula bullets present (what found / what changes / what's open)"
    threshold: 3
    scale: 4
  - name: calibrated_uncertainty
    description: "Caveats and open questions preserved; no false confidence"
    threshold: 3
    scale: 4
aggregate_threshold: 0.7
rejection_rules:
  - dimension: calibrated_uncertainty
    condition: "< 2"
    verdict: FAIL
    note: "Applies regardless of aggregate score"
```

### Discriminability check design

A rubric that always passes or always fails is useless. Check must produce at least 3 PASS and 3 FAIL verdicts across 10 samples. Samples should be crafted to cover the full variance spectrum:

**Clear FAIL cases (2-3 samples):**
- Message with no formula bullets (missing completeness)
- Message with false confidence, no caveats (calibrated_uncertainty = 1 → explicit rejection rule fires)
- Message with vague claims, no artifact references (evidence_traceability = 1)

**Clear PASS cases (2-3 samples):**
- Message with all 3 formula bullets, clear citations, appropriate uncertainty
- Message that is minimal but meets all thresholds

**Borderline cases (4-5 samples):**
- Message missing one formula bullet (completeness borderline)
- Message with some but not all claims referenced
- Message with one ambiguous referent but otherwise clear

Since discriminability can be checked without live API calls (by mocking `call_judge` with realistic score distributions), implement a discriminability script that:
1. Defines 10 sample messages inline
2. For each, manually specifies expected scores (simulating what Haiku would score)
3. Runs them through the scoring/verdict logic of `judge_communication` (not the API call part)
4. Reports pass/fail distribution
