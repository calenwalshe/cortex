## Summary

Git worktrees are the proven solution for parallel AI agent builds — used by Claude Code, Cursor, and Codex. GSD already has `/gsd:new-workspace` which creates worktree-based workspaces with independent `.planning/` directories. The Cortex integration needs three things: (1) a per-worktree `.cortex/state.json` so each slug has its own state, (2) a `/cortex-workspace` command that creates a worktree + initializes Cortex state for a slug, and (3) a merge-back workflow when the parallel build completes. The failure case research is critical: merge conflicts from shared files (settings.json, hooks, CLAUDE.md) are the #1 pain point — the design must isolate execution while sharing the Cortex framework files.

## External Research (7 searches, 4 providers, $0.130)

### Search 1: Parallel AI Agent Patterns — SEED (Perplexity, $0.016)

**Confirmed:** Git worktrees are the standard for parallel AI coding agents. Claude Code, Cursor, and Codex all use them. Key benefits: context isolation, preserved conversation history, safe experimentation, lightweight (shared .git objects).

**Tools ecosystem:** worktree-cli (MCP integration), ccswarm (multi-agent pools), Crystal (desktop app for parallel sessions), git-wt (auto-naming + env copying).

### Search 2: Claude Code Worktree Support — VOCABULARY (Gemini, $0.038)

**Native support:** `claude --worktree <name>` creates worktree + starts session. Agent tool `isolation: "worktree"` parameter creates temporary worktrees for subagents with automatic cleanup.

**Key mechanics:**
- Worktrees created under `.claude/worktrees/` by default
- Each gets its own branch
- `CLAUDE_PROJECT_DIR` points to the worktree, not main repo
- Add `.claude/worktrees` to `.gitignore`

### Search 3: Coordination Patterns — REFINE (Tavily, $0.016)

**Port allocation:** `BASE_PORT + (WORKTREE_INDEX * 10) + SERVICE_OFFSET`
**Per-worktree env:** Scripts that auto-copy .env and configure per-worktree settings
**Merge detection:** Analyze task independence before parallel execution; warn when agents approach same code regions
**Existing tools:** git-worktree-setup skill on MCP market handles lifecycle, port mapping, env config

### Search 4: Worktree Architecture — DEEP DIVE (Jina, $0.0001)

**From Upsun article (2026-02-11):**
- Worktree = linked working directory sharing `.git` data
- Each has `.git` file (not folder) pointing to main repo
- `git fetch` updates all worktrees at once
- Commits in any worktree visible to all others

**Where worktrees fall apart:**
- Port conflicts (every dev server defaults to 3000/5432/8080)
- Dependency duplication (node_modules per worktree)
- Unversioned files (.env, secrets) need manual setup
- Merge conflicts NOT eliminated — just deferred to merge time

### Search 5: Failure Cases — FAILURE CASES (Perplexity, $0.021)

**Top failure modes for parallel AI agents:**

| Category | Prevalence | Specific Issue |
|----------|-----------|----------------|
| Specification/Design | 37% | Agents disobey Git protocols, no pre-commit hooks |
| Inter-Agent Misalignment | 31% | No merge notifications, concurrent diffs ignored |
| Verification/Termination | 31% | No build/merge success checks, stalled state |

**Specific problems:**
- File contention: agents editing same files concurrently
- State desync: one agent updates config while another reads stale data
- Reasoning loops: repeated git merge --abort due to ambiguous feedback
- Build corruption: concurrent npm installs corrupt node_modules

**Mitigation consensus:** One agent per worktree, enforce roles, structured messaging between agents, LLM-as-Judge on merge results.

### Search 6: State Sharing Across Worktrees — IMPL (Perplexity, $0.019)

**Git worktree file isolation:**
- Shared: .git/config, refs, objects, history
- Isolated: working directory, index, HEAD, config.worktree

**Patterns for state files:**

| Pattern | When to use |
|---------|------------|
| Symlinks to main | Shared deps, .env, framework files |
| Ignore + copy | Config needing occasional sync |
| Repo-level shared dir | Persistent shared settings (committed) |
| Per-worktree isolation | State that must not conflict (state.json) |

## Internal Architecture Findings

### GSD `/gsd:new-workspace` — Already Solves Execution Isolation

GSD's workspace system:
1. Creates worktree or clone per repo
2. Each workspace gets independent `.planning/` directory
3. Writes `WORKSPACE.md` manifest
4. Supports `--strategy worktree` (lightweight, recommended) or `--strategy clone`
5. Branch naming: `workspace/{name}` with timestamp fallback

**This means GSD execution isolation is already solved.** Each parallel build can have its own `.planning/` in its own worktree.

### What Cortex Needs on Top

GSD handles `.planning/` isolation. Cortex needs to handle:

| File | Current | Parallel Need |
|------|---------|---------------|
| `.cortex/state.json` | One active slug | **Per-worktree** — each slug needs its own state |
| `.cortex/facts.jsonl` | Shared | **Shared is OK** — append-only, slug-tagged |
| `.cortex/supervisor.jsonl` | Shared | **Shared is OK** — append-only |
| `.cortex/fact-embeddings.npy` | Shared | **Shared is OK** — read-only during retrieval |
| `docs/cortex/handoffs/current-state.md` | One slug | **Per-worktree** — each slug tracks its own state |
| `docs/cortex/handoffs/decisions.md` | Shared log | **Shared is OK** — append-only |
| `docs/cortex/clarify/{slug}/` | Per-slug | **Already isolated** |
| `docs/cortex/research/{slug}/` | Per-slug | **Already isolated** |
| `docs/cortex/specs/{slug}/` | Per-slug | **Already isolated** |
| `docs/cortex/contracts/{slug}/` | Per-slug | **Already isolated** |
| `.claude/settings.json` | Shared | **Shared is OK** — read-only for hooks |
| `.claude/hooks/` | Shared | **Shared via symlinks** — same hooks in all worktrees |

**Only 2 files need per-worktree isolation:** state.json and current-state.md. Everything else is already either per-slug (isolated by directory) or append-only (safe for concurrent access).

## Design Decisions — All Resolved

### 1. Isolation Strategy → Git worktree per slug (via GSD workspace)

**Decision:** Each parallel slug gets its own git worktree created by `/gsd:new-workspace`. Cortex initializes per-worktree state in the worktree's `.cortex/state.json`.

**Why:** Worktrees provide working directory isolation while sharing git history. GSD already handles .planning/ isolation. Cortex just needs to initialize its own state per-worktree.

### 2. State Isolation → Per-worktree .cortex/ directory

**Decision:** Each worktree gets its own `.cortex/` directory with its own state.json. The main repo's `.cortex/` is not shared.

**Why:** `.cortex/` is gitignored. In a worktree, gitignored files are per-worktree (they live in the working directory, not in .git). So state.json is automatically isolated — no code change needed.

**Verification needed:** Confirm that `.cortex/` in a worktree is indeed independent from the main repo's `.cortex/`.

### 3. Shared Files Strategy → Symlinks for framework, isolation for state

**Decision:**
- `.claude/hooks/` → already symlinked from main repo (installer creates symlinks into `~/.claude/hooks/`)
- `.claude/settings.json` → read by Claude Code from the project dir, so each worktree has its own copy (part of the working tree)
- `docs/cortex/` → per-slug artifacts are already isolated; shared files (decisions.md) tolerate concurrent appends

### 4. Merge Strategy → PR per slug, merge to main when complete

**Decision:** Each worktree works on its own branch (`workspace/{slug}`). When the build completes and validators pass, create a PR to main. Human reviews and merges. If two slugs modified the same file, the second PR gets a merge conflict that the human resolves.

**Why not auto-merge:** The failure case research shows 31% of parallel agent failures come from inter-agent misalignment during merges. Human review at merge time is the safest pattern.

### 5. cortex-drive Coordination → No coordination needed

**Decision:** Parallel drive loops don't need to know about each other. Each operates in its own worktree with its own state.json, its own .planning/, and its own branch. They're fully independent.

**Why:** The worktree provides physical isolation. The only shared surface is the git object database, which git handles natively. Concurrent commits to different branches don't conflict.

### 6. Workflow → New command: `/cortex-parallel <slug> <idea>`

**Decision:** A thin wrapper that:
1. Creates a worktree via `/gsd:new-workspace --name {slug} --strategy worktree --auto`
2. Initializes `.cortex/state.json` in the worktree
3. Starts `/cortex-drive <idea>` in the worktree (via a new terminal session)

The user opens a new terminal, cd's into the worktree, and runs `claude` — getting a fresh session with its own Cortex state.

**Alternative considered:** Spawning an Agent with `isolation: "worktree"`. This works for subagent tasks but not for full drive loops — the drive loop needs its own persistent session with its own context window, not a subagent that returns a result.

## Implementation Shape

### What to build:

1. **`/cortex-parallel` skill** — creates worktree, initializes Cortex state, prints instructions for the user to open a new terminal
2. **Worktree initialization** — creates `.cortex/state.json`, copies `docs/cortex/handoffs/` templates, ensures hooks work
3. **Merge-back guidance** — after drive completes in worktree, PR to main

### What NOT to build:

- No inter-agent messaging (isolation is sufficient)
- No shared state coordination (per-worktree .cortex/ handles it)
- No custom merge tooling (git + PRs handle it)
- No daemon or coordinator (just worktrees + independent sessions)

### The simple version:

```bash
# User runs in main repo:
/cortex-parallel my-feature "build the feature X"

# This creates:
#   .claude/worktrees/my-feature/  (worktree on branch workspace/my-feature)
#   .claude/worktrees/my-feature/.cortex/state.json  (initialized)
#   .claude/worktrees/my-feature/.planning/  (empty, ready for GSD)

# User opens new terminal:
cd .claude/worktrees/my-feature
claude
# > /cortex-drive "build the feature X"
# Drive loop runs independently in the worktree
```

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Isolation | Git worktree | Clone / Docker / VM | Worktrees are lightweight, share history, GSD already supports them |
| State | Per-worktree .cortex/ | Multi-slug state.json | gitignored files are already per-worktree; zero code change |
| Coordination | None (independent) | Shared memory / messaging | Isolation eliminates the need; 31% failure rate from coordination |
| Merge | PR per slug, human review | Auto-merge | Failure research: inter-agent merge is #1 failure mode |
| Entry point | New terminal per slug | Agent subagent | Drive loops need persistent sessions, not subagent results |
