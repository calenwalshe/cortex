## Summary

The existing `ccstatusline` script at `/home/agent/bin/ccstatusline` is **broken**, not just missing Cortex fields. It uses wrong Claude Code schema assumptions: it reads `d.get('model')` as a string when Claude Code sends `model` as a dict with `display_name`, reads `d.get('context', {}).get('used')` when the real field is `context_window.total_input_tokens`, and reads `cwd` when the real field is `workspace.current_dir`. The render output `agent@agent-stack-dev | ? | ? | ctx: 0%` shows three broken fields. The fix is rewriting the script to use the correct schema and adding Cortex signals (active slug, mode, approval status) from `.cortex/state.json`.

## Findings

- **Claude Code status line API (Q1 factual — Perplexity):** Configured via `statusLine` in `settings.json` with `{"type": "command", "command": "path/to/script"}`. Claude Code pipes JSON to script stdin on each update; stdout becomes the status line. Refresh interval configurable via `refreshInterval` (default varies). Key JSON fields:
  - `model.display_name` (e.g., "Opus") and `model.id` (full ID)
  - `context_window.total_input_tokens`, `context_window.total_output_tokens`, `context_window.context_window_size`, `context_window.used_percentage`
  - `cost.total_cost_usd` (session cost)
  - `workspace.current_dir` (NOT `cwd`)
  - `worktree.name` (git worktree)
  - `rate_limits.five_hour.used_percentage`
  - Source: Perplexity synthesis of Claude Code docs (code.claude.com/docs/en/statusline).

- **Current ccstatusline script is broken (Q2 codebase — direct read):** Script at `/home/agent/bin/ccstatusline` assumes wrong schema:
  - Line 19: `model = d.get('model', '?')` — but `model` is a dict, not a string. Result: Python treats dict as string, calls `.startswith('claude-')` which errors.
  - Line 29: `cwd = d.get('cwd', os.getcwd())` — wrong field name. Should be `d.get('workspace', {}).get('current_dir')`.
  - Line 34: `ctx_used = d.get('context', {}).get('used', 0)` — wrong path. Should be `d.get('context_window', {}).get('total_input_tokens', 0)` + output tokens.
  - Empirical test with correct schema JSON: `AttributeError: 'dict' object has no attribute 'startswith'` and `CTX_TOTAL: unbound variable`.
  - The "missing info" the user perceives is actually **broken rendering**, not fields that were never added.

- **Community status line patterns (Q3 landscape — Tavily):** Common modules: directory (last 3 segments), git_branch (with worktree indicator), model, cost (color-coded by thresholds: yellow $1, red $5), context (progress bar, yellow 50%, red 90%). Disabled-by-default: session_timer, lines_changed. Community scripts like `claude-statusline` (felipeelias) use TOML configs with theme presets. Format strings like `$model | $directory | $git_branch | $cost` are typical. Source: felipeelias.github.io/claude-statusline, code.claude.com/docs.

- **Cortex signals worth surfacing (Q4 codebase — direct analysis of `.cortex/state.json`):** The state schema provides: `slug`, `mode` (clarify/research/spec/execute/done), `approval_status` (pending/approved/rejected), `active_contract`, `gates` (clarify_complete, research_complete, spec_complete, contract_approved, pr_opened, pr_merged). The high-value subset for status line:
  1. `slug` — which work item is active
  2. `mode` — current lifecycle phase
  3. `approval_status` — whether user action is needed
  4. Derived warning: if `mode=execute` but `contract_approved=false`, something is wrong
  The full gates object is too verbose for a status line; the mode + approval_status combo captures most of it.

## Trade-offs

### Option: Rewrite ccstatusline to fix schema + add Cortex signals (single script)
**Pros:** One place to edit, minimal files changed. Script already exists and is invoked by settings.json. Keeps the current wrapper contract.
**Cons:** The script is bash+Python — mixing languages. Adding Cortex state reads makes it longer.
**Verdict:** selected — simplest possible fix. Keep bash+Python (already there), fix the schema, add Cortex state parsing.

### Option: Replace ccstatusline with a community tool (e.g., claude-statusline by felipeelias)
**Pros:** Maintained externally, better theming, TOML config.
**Cons:** Requires install, external dependency, doesn't support Cortex signals natively (would still need a wrapper), changes the user's workflow.
**Verdict:** rejected — the user wants to fix what they have, not migrate.

### Option: Multi-line status line (git info on line 1, Cortex + context on line 2)
**Pros:** More room for info, cleaner visual grouping.
**Cons:** Takes up more screen space, and the user's framing was "add missing info" not "reorganize layout."
**Verdict:** deferred — possible future enhancement, not in this scope.

## Recommendations

- **Rewrite `/home/agent/bin/ccstatusline` with correct Claude Code schema:**
  - Parse `model.display_name` (dict access, not string)
  - Parse `workspace.current_dir` (not `cwd`)
  - Parse `context_window.total_input_tokens` + `total_output_tokens` / `context_window_size` for percentage
  - Parse `cost.total_cost_usd` for session cost display

- **Add Cortex state parsing:** Read `$CLAUDE_PROJECT_DIR/.cortex/state.json` if it exists. Extract `slug`, `mode`, `approval_status`. If `slug` is null, show nothing Cortex-related. If `mode=execute` and `approvals.contract=false`, prefix with a warning marker.

- **Target format** (single line, pipe-separated for reading ease):
  ```
  {user}@{host} | {model} | {cwd} | ctx:{pct}% | ${cost} | [{slug}:{mode}{approval_marker}]
  ```
  Example: `agent@agent-stack-dev | opus 4.6 | ~/projects/cortex | ctx:45% | $0.14 | [claude-code-status-line:clarify]`
  Example with warning: `[research-depth-routing:execute ⚠]` (warning when contract not approved but in execute mode)
  Example with no slug: trailing `[none]` section omitted entirely.

- **Graceful degradation:** If `.cortex/state.json` doesn't exist or can't be parsed, omit the Cortex section entirely (don't error). If any Claude Code field is missing, show `?` instead of crashing. The current script has `set -euo pipefail` — keep it, but guard each field access.

- **Test before saving:** Pipe sample JSON through the new script, verify output format before replacing the live version.
