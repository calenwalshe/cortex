## Summary

The research phase should add a structured "Adjacent Findings" section (0-3 items max) using a VOI-gated filter pipeline. The strongest implementable approach combines multi-angle query reformulation (from IC Outside-In Thinking and Consensus's 20-query method), graph/citation-based relatedness signals (from Semantic Scholar's SPECTER approach), and aggressive filtering via a 4-dimension scoring model (Impact, Novelty, Specificity, Timeliness). Each finding must carry a BLUF-formatted relevance justification. No existing tool does this well end-to-end — the gap is specifically in bisociative cross-domain discovery, opportunity analysis (vs. threat-only), and assumption-indicator generation.

## Findings

### The Core Filter: Value of Information (VOI)

- A finding has zero value if the optimal decision is the same regardless of what it reveals. This is the mandatory gate — nothing passes without decision-relevance
- VOI from decision theory provides the formal framework: Expected Value of Perfect Information (EVPI) sets the upper bound on what any piece of information is worth
- The IC's "So What?" protocol operationalizes VOI with three sub-questions: What does this mean? How does it affect the decision-maker? What happens next?
- If a finding can't answer all three, it doesn't make the brief

### The 4-Dimension Scoring Model

- **Impact** (would this change a decision?) — mandatory gate, binary pass/fail
- **Novelty** (does the user likely already know this?) — filters obvious/generic advice. Maps to Bayesian surprise (KL divergence between prior and posterior beliefs)
- **Specificity** (concrete to this project or universally applicable?) — the 80% test: if it applies to most projects, filter it out
- **Timeliness** (relevant now or later?) — late-relevant findings get stashed with trigger conditions, not surfaced now
- Minimum threshold: must score 1 on Impact AND at least one other dimension
- Rank ties broken by Impact × Novelty (Bayesian surprise approximation)

### Cognitive Load Constraints

- Modern working memory research: 4±1 items for novel information (revised down from Miller's 7±2)
- Adjacent findings are by definition outside the user's focus → novel → lower bound applies
- **Hard cap: 1-3 findings per research pass.** Zero is valid — don't pad. Never surface findings just to fill a quota
- Information overload research: filter before exposure, don't delegate filtering to the user

### What Existing Tools Do (and Don't)

- **Google PAA**: Query-log mining + entity recognition from real user behavior. Useful for novices, low value for experts — surfaces common questions, not surprising ones
- **Perplexity**: RAG-based follow-up generation. Context-aware but trajectory-following — logical next steps, not orthogonal perspectives
- **Gemini Deep Research**: Strongest existing product — iterative replanning that identifies what's missing at each step. Proactively suggests related resources and additional deep dives
- **Semantic Scholar SPECTER**: Citation-graph embeddings capture intellectual relatedness that transcends keyword overlap. Two papers can be deeply related through shared citations using completely different vocabulary
- **Consensus**: 20 varied search reformulations is an explicit adjacent discovery mechanism — reaches papers a single query misses
- **Tavily**: Zero adjacent discovery features — pure retrieval. Any discovery must be built on top
- **No tool does bisociative cross-domain discovery**, opportunity analysis, assumption-indicator generation, or mirror-imaging correction

### IC Tradecraft Techniques (Directly Applicable)

- **Outside-In Thinking**: Systematic domain checklist (political, economic, technological, legal, social, environmental). For each domain not already covered in research, flag it as a potential blind spot
- **Indicators & Warnings**: Decompose assumptions into falsifiable indicators. Generate "what would prove this approach wrong?" questions — a net-new capability no research tool provides
- **Analysis of Competing Hypotheses (ACH)**: Treat all plausible explanations equally. Don't try to prove one theory — identify evidence that discriminates between hypotheses
- **Mirror Imaging**: The central cognitive trap — an LLM projects its training distribution onto the user's problem space. Countermeasure: explicitly adopt perspectives that disagree with the user's approach (Red Team Analysis)
- **Opportunity Analysis**: Most research is threat-oriented ("what could go wrong?"). Opportunity analysis asks: "what favorable conditions exist that the user hasn't noticed?" — no existing tool does this

### Prompt Engineering That Works

- **"Wait" trigger**: 89.3% reduction in blind spots by appending "Wait" to trigger self-correction
- **Analytic hints injection** (IBM/AAAI 2026): Domain experts flag recurring LLM blind spots, inject as hints → error detection from 45% to 94%
- **Steelman-the-alternative**: Construct the strongest argument for the opposite view. Daniel Dennett's protocol: re-express the other position so clearly they'd agree with the phrasing
- **Domain-specific expert framing**: "What would a [specific expert type] be surprised I didn't ask?" — specificity prevents generic filler
- **Generic "what am I missing?" prompts fail** — produce platitudes without domain anchoring

### Theoretical Foundations

- **Adjacent Possible** (Kauffman): Good adjacent discovery = findings one step beyond current knowledge. Not five rooms away (incomprehensible) and not the room you're already in (obvious)
- **Bisociation** (Koestler): Creative insight comes from connecting independent, autonomous frames of reference. The highest-value adjacent findings connect the user's domain to a structurally similar but vocabularily different domain
- **Information Foraging Theory** (Pirolli & Card): Users maximize information gain per unit time. The "why it matters" sentence IS the information scent — without it, users rationally ignore adjacent material

## Trade-offs

### Option: Inline section in existing research dossier
**Pros:** No new artifact type. Findings appear in context alongside primary research. Consistent with existing template structure. Low ceremony.
**Cons:** May get lost in long dossiers. No standalone reference for adjacency quality tracking.
**Verdict:** Selected. Add an "## Adjacent Findings" section to the research dossier template, between Recommendations and Open Questions.

### Option: Separate companion artifact
**Pros:** Clean separation. Can track adjacency quality independently. Doesn't bloat the primary dossier.
**Cons:** Extra file for 0-3 findings feels over-engineered. User must read two documents. Violates owner-intent "low ceremony" constraint.
**Verdict:** Rejected. Not worth the overhead for 0-3 items.

### Option: Multi-angle query reformulation (Consensus-style)
**Pros:** Proven mechanism — 20 varied searches reaches papers a single query misses. IC Outside-In Thinking provides a systematic checklist for angles. Low implementation cost (just run additional searches).
**Cons:** Increases research phase wall time. More API calls = higher cost. May surface noise without good filtering.
**Verdict:** Selected, with constraint: limit to 3-5 reformulated queries (not 20). Use Outside-In checklist to select the most relevant angles. Must be gated by the VOI filter before surfacing.

### Option: Citation/reference graph traversal
**Pros:** SPECTER-style embeddings find related work that shares no keywords. Captures intellectual lineage. Semantic Scholar API is free.
**Cons:** Only works for academic/documented knowledge — not for emerging tools, community practices, or proprietary knowledge. Adds a dependency on Semantic Scholar API.
**Verdict:** Deferred. Good for academic research contexts but too narrow for Cortex's general-purpose use case. Revisit if research-heavy slugs become common.

### Option: Assumption-indicator generation (from I&W framework)
**Pros:** Unique capability no existing tool provides. "Here's what would prove your approach wrong" is extremely high-value adjacent discovery. Maps directly to the clarify brief's Assumptions section.
**Cons:** Requires the model to reason about assumptions, which is subjective. Risk of false indicators (things that sound like they'd prove you wrong but actually wouldn't).
**Verdict:** Selected as a sub-component. For each assumption in the clarify brief, generate one falsifiable indicator. Surface only indicators that score >0 on Impact + Novelty.

## Recommendations

- **Add an "## Adjacent Findings" section to the research dossier template** between Recommendations and Open Questions. Format: 0-3 items, each as BLUF (finding + why-it-matters + source). Zero is valid — never pad
- **Implement the 6-stage filter pipeline** in the research skill instructions:
  1. Decision-relevance gate (VOI: would this change a decision?)
  2. Specificity gate (80% test: does this apply to most projects?)
  3. Novelty check (does the user likely already know this?)
  4. Timeliness check (relevant now vs. later? → stash if later)
  5. Format as BLUF
  6. Hard cap at 3, ranked by Impact × Novelty
- **Add 3-5 reformulated queries** during the research phase using Outside-In angles (political/economic/technological/legal/social/environmental — pick the 3-5 most relevant to the slug). This is the discovery mechanism; the filter pipeline prevents noise
- **Generate assumption indicators** from the clarify brief: for each stated assumption, produce one falsifiable indicator ("if you observe X, this assumption is wrong"). Surface only the most decision-relevant ones
- **Add a "Wait" self-check** before finalizing the dossier — the research skill should explicitly ask itself "what did I not consider?" after drafting findings but before writing the artifact. The 89.3% blind spot reduction justifies the trivial cost
- **Do NOT add citation graph traversal yet** — too narrow for general use. Revisit when academic research contexts become a regular Cortex use case
- **Do NOT implement opportunity analysis as a separate feature** — instead, include "favorable conditions" as one of the Outside-In angles. Opportunity framing is a perspective, not a mechanism

## Open Questions

- How do we measure adjacency quality over time? A/B testing is impractical with one user. Possible: track how often the user engages with adjacent findings (reads, asks follow-up, incorporates into spec) vs. ignores them
- Should the "stash with trigger condition" path for late-relevant findings connect to Cortex's existing stash system (`/cortex-stash`)?
- How do we calibrate the novelty dimension — the model doesn't know what the user already knows. Can we use memory (user profile, prior research) to estimate?
- The "Wait" self-check technique is from a 2026 paper — how robust is it across different LLM architectures? Is it Claude-specific or general?
- Should adjacent findings contribute to the research dossier's Open Questions section when they raise questions the primary research didn't address?
