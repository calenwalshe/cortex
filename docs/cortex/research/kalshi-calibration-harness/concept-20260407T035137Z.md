## Summary

The concept is not only feasible but empirically validated by recent research. Kalshi provides full programmatic API access (REST + WebSocket, official Python SDK, demo sandbox) with explicit permission for automated trading. LLMs are projected to reach superforecaster-level forecasting by November 2026, and outcome-based RL on prediction market resolutions has already been shown to produce calibrated, economically valuable forecasters (arXiv 2505.17989). The optimal starting strategy is daily weather markets (fastest feedback, highest research-amenability, lowest institutional competition), supplemented by weekly entertainment and monthly economics markets. You need 500-1000 resolved predictions for statistically meaningful calibration assessment, achievable in ~2-3 months with weather markets. The hardest unsolved problem is not forecasting accuracy but the execution gap — profitable trading requires capturing the spread, not just being directionally correct.

## Findings

### Kalshi Platform Viability

- Full REST API with RSA-PSS authentication, official Python SDK (`kalshi-python` on PyPI), WebSocket real-time feeds, and a demo sandbox environment for testing
- Automated/algorithmic trading explicitly permitted — Kalshi provides the API specifically for this purpose
- Basic tier: 20 reads/sec, 10 writes/sec — sufficient for a research-focused calibration system
- KYC required (US resident, 18+, SSN). Minimum deposit $10. Funding via ACH (free), debit (2% fee), wire ($1K min), or crypto (USDC/BTC/SOL)
- Settlement is unambiguous: market objects include `status` (open/closed/settled), `result` (yes/no), and settlement price — full programmatic outcome verification
- Position tracking, fill history, and P&L all accessible via API endpoints

### Calibration Science

- **Brier score** is the standard metric: 0 = perfect, 0.25 = coin flip. Decomposes into reliability (calibration penalty), resolution (discrimination ability), and uncertainty (base rate property)
- **Log loss** preferred when false confidence is especially costly — penalizes confident wrong predictions exponentially harder than Brier
- **Calibration curves** (reliability diagrams) require binning predictions by stated probability and comparing to observed frequency. Minimum 20-30 predictions per bin
- **Statistical thresholds**: 50 predictions = rough directional sense; 200 = basic 5-bin curve; 500 = reliable 10-bin curve; 1000+ = gold standard with fine-grained detection
- **Critical nuance**: total predictions matter less than predictions *per probability bucket*. Deliberate practice at varied confidence levels accelerates calibration learning

### LLM Forecasting State of the Art

- ForecastBench (ICLR 2025): GPT-4.5 Brier score 0.101 vs. superforecasters at 0.081. LLM performance improves ~0.016 Brier points/year. **Projected parity: November 2026**
- "Wisdom of the Silicon Crowd" (Science Advances 2024): ensemble of 12 LLMs statistically indistinguishable from 925 human forecasters. Human-LLM hybrids improved accuracy 17-28%
- Outcome-based RL (arXiv 2505.17989): 14B model trained on 110K events matches o1 on accuracy while beating it on calibration (ECE 0.042). A simple trading rule converts this into $127 hypothetical profit vs. $92 for o1
- **Key failure mode**: GPT-4.5 predictions correlate 0.994 with provided market forecasts — models anchor to market prices rather than forecasting independently when given market context. The Cortex pipeline must withhold market prices during the research phase

### Market Category Selection

- **Tier 1 — Daily Weather**: 100+ markets/day across 17 US cities. NWS/GFS/ECMWF model outputs are public and free. Most casual traders don't read ensemble model output — genuine information asymmetry. Daily resolution = 20-30 trades/week achievable. **Best category for fast calibration feedback**
- **Tier 2 — Weekly Entertainment (Rotten Tomatoes)**: Resolves Monday after opening weekend. Researchable via festival reviews, early critic embargo lifts, director track records. Low institutional competition. 3-5 trades/week during release season
- **Tier 3 — Monthly Economics (CPI, Jobs)**: Unambiguous resolution via BLS/Fed data. Researchable via Cleveland Fed Nowcast, regional surveys, TIPS breakevens. Only 2-3 trades/month but builds deeper analytical discipline
- **Avoid**: Daily finance/crypto (near-random, quant-dominated), sports (speed-of-information game, not analysis game), long-dated politics (too slow for feedback loops)

### Post-Mortem and Failure Attribution

- A 10-code failure taxonomy maps cleanly to Cortex pipeline phases:
  - F1 Framing Error → Clarify phase
  - F2 Information Gap, F3 Source Quality → Research phase
  - F4 Base Rate Neglect, F5 Weighting Error, F6 Model Error → Analysis phase
  - F7 Update Failure → Monitoring (net-new phase needed)
  - F8 Calibration Error → Calibration layer (net-new)
  - F9 Challenge Failure → Critic/Review phase
  - F10 Outcome Variance → No phase (correct process, tail outcome)
- **Cannot distinguish process failure from outcome variance on a single prediction** — must analyze in batches. Need 200+ predictions to detect systematic biases
- Annie Duke's "resulting" (judging decisions by outcomes) is the cardinal sin of prediction post-mortems. The post-mortem template must include a "was this a process failure or outcome variance?" gate before root cause analysis
- Best post-mortem format: Army AAR — (1) What was supposed to happen? (2) What actually happened? (3) Why the difference? (4) What changes?

### AI Trading Landscape

- 14 of 20 most profitable Polymarket wallets are bots. 30%+ of wallets use AI agents
- **Critical finding: profit comes from execution, not prediction.** Traders with above-random accuracy earn *negative* returns because they arrive late and pay unfavorable prices. Traders with near-random accuracy earn positive returns through execution quality (2.52 cents price improvement per contract)
- Superforecasters beat Polymarket on 76% of forecast days — markets are not perfectly efficient, alpha exists, but capturing it requires solving the execution problem
- The most defensible edge is not raw forecasting but the **meta-cognitive improvement loop** — using outcomes to systematically improve the reasoning pipeline. This is exactly the Cortex thesis
- Kalshi taker fees start at 0.2% with maker rebates of 0.05%. At a 55% win rate, fees eat the entire edge — must trade at limit prices

## Trade-offs

### Option: Start with demo sandbox (paper trading)
**Pros:** Zero financial risk. Can iterate on pipeline structure without stakes. Full API access in demo environment.
**Cons:** Defeats the core thesis — real money is the point. Paper trading doesn't produce the same cognitive engagement or honest post-mortems. No genuine "skin in the game" signal.
**Verdict:** Use demo for API integration testing only (1-2 days), then switch to real money immediately. Even $5 per trade produces genuine signal.

### Option: Weather markets as primary calibration instrument
**Pros:** Daily resolution (fastest feedback), public NWS/model data (genuine research edge), low institutional competition, 100+ markets/day (statistical significance in weeks not months). 500 predictions achievable in ~3-4 weeks.
**Cons:** Narrow domain may not generalize — being calibrated on weather doesn't prove calibrated on geopolitics. Limited market depth on some cities.
**Verdict:** Selected as Tier 1. Mitigate domain narrowness by adding Tier 2/3 categories after initial calibration baseline is established.

### Option: Brier score vs. log loss as primary metric
**Pros of Brier:** Bounded [0,1], intuitive, decomposes into reliability/resolution/uncertainty, standard in forecasting community.
**Pros of log loss:** Severely penalizes confident wrong predictions — forces intellectual honesty about tail risk. Standard in ML training pipelines.
**Cons of Brier:** Less sensitive to extreme miscalibration. **Cons of log loss:** Unbounded, harder to interpret, a single catastrophic miss dominates the score.
**Verdict:** Use Brier as the primary tracking metric (comparability with forecasting literature), log loss as a secondary "honesty check" metric. Both are trivially computable.

### Option: Withhold market prices during research phase
**Pros:** Prevents the documented anchoring problem (GPT-4.5 correlates 0.994 with provided market prices). Forces independent reasoning. The delta between your probability and market price becomes the "edge signal."
**Cons:** Ignores valuable information — market prices aggregate other participants' knowledge. May lead to systematically worse predictions.
**Verdict:** Selected. Withhold market price during research/analysis. Reveal at the "position sizing" stage — the spread between your estimate and market price determines whether to bet and how much. This is how the system detects edge.

### Option: Kelly criterion for position sizing
**Pros:** Mathematically optimal growth rate. Automatically sizes bets proportional to edge. Prevents over-betting on thin edges.
**Cons:** Requires accurate edge estimation (circular — the whole point is we don't know our edge yet). Full Kelly is too aggressive for estimation error. Fractional Kelly (1/4 or 1/2) is standard practice.
**Verdict:** Deferred to implementation research. Start with flat $5-10 per trade during calibration phase. Introduce fractional Kelly once calibration baseline is established (~200+ predictions).

### Option: Fork as separate GitHub repo vs. long-lived branch
**Pros of fork:** Clean separation, independent issues/CI, prevents accidental pollution of mainline Cortex. Bidirectional cherry-picking via upstream/downstream remotes.
**Cons of fork:** More ceremony than a branch. Two repos to maintain.
**Verdict:** Selected (fork). The work is directionally different enough that a branch would create confusion. Cherry-pick proven general-purpose improvements back to mainline.

## Recommendations

- **Create the GitHub fork immediately** (`cortex-kalshi`) with bidirectional remotes to mainline Cortex. Start building on the fork from day one
- **Begin with weather markets in 2-3 cities** (NYC, Chicago recommended for data depth). Target 20-30 trades/week. This produces 500 predictions in ~3-4 weeks — enough for a reliable calibration curve
- **Design the bet record schema** as the first implementation task. Minimum fields: market_ticker, entry_timestamp, your_probability, market_price_at_entry, position_side, stake_amount, resolution_outcome, brier_contribution, post_mortem_path. Store as JSONL (consistent with Cortex's existing event log format)
- **Build the pipeline as: research (price-blind) → calibrate (probability estimate) → compare (reveal market price, compute edge) → decide (bet/pass) → resolve → post-mortem**. The price-blind research phase prevents the documented LLM anchoring problem
- **Use the F1-F10 failure taxonomy** in post-mortems. After each batch of 50 predictions, compute the distribution of failure codes to identify which pipeline phase needs the most investment
- **Track both Brier score and calibration curves** from trade 1. Even with small samples, the trajectory (improving vs. degrading) is informative before the numbers stabilize
- **Start with flat stakes ($5-10/trade)** during the calibration phase. The goal is learning signal, not profit. Introduce position sizing (fractional Kelly) after the first reliable calibration curve (~500 predictions)
- **Add a "monitoring" phase to the pipeline** — Cortex currently has no equivalent. Markets evolve between bet placement and resolution; the system needs a mechanism to update positions when new evidence arrives
- **Accept that early P&L will likely be negative.** This is the cost of calibration data. Budget $500-1000 as "tuition" for the first 500 predictions. If the system is well-calibrated, it should approach breakeven as sample size grows

## Open Questions

- **Monitoring/update phase design**: Cortex has no equivalent of "new evidence arrived, should I update my position?" How does this phase integrate with the existing pipeline? Does it trigger a mini-research cycle?
- **Multi-market portfolio construction**: When trading weather across multiple cities simultaneously, how do we handle correlated outcomes (e.g., a cold front affecting Chicago and NYC on the same day)?
- **Calibration layer architecture**: Should probability estimation be a separate Cortex skill (e.g., `/cortex-calibrate`) or embedded in the research phase? The former is more modular; the latter avoids pipeline bloat
- **Execution strategy**: Limit orders vs. market orders? The research shows execution quality matters more than prediction quality for profitability. What maker/taker strategy optimizes for the calibration use case?
- **When to graduate from weather to multi-domain**: After how many predictions / what Brier score threshold should the system expand to Tier 2/3 categories?
- **Human-AI hybrid mode**: Research shows 17-28% accuracy improvement from human-LLM hybrids. Should the pipeline support a mode where the human reviews and adjusts the AI's probability estimate before placing the bet?
- **Adversarial dynamics**: As more AI enters prediction markets, the easy edge disappears. How do we detect when our edge is being arbitraged away?
