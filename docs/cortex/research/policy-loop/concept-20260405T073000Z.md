## Summary

The policy loop is a solved problem architecturally. External research across Perplexity, Gemini, Tavily, and Jina confirms the production standard is a **hybrid state machine with LLM-bounded decisions** — deterministic transitions for the spine, LLM reasoning only at bounded decision points. GSD already implements exactly this pattern in `/gsd:drive` with an artifact-based decision table. The failure case research revealed critical guardrails: error compounding drops multi-step success to <15% without feedback loops, the Replit 2025 incident showed agents can ignore constraints and cause data loss, and context drift from overloading is a documented production failure mode. These inform the stopping conditions and safety design.

## External Research (6 searches, 4 providers, $0.131 total)

### Search 1: Agent Orchestration Patterns — SEED (Perplexity, $0.019)

**State of the art (2025-2026):** Hybrid state machine + LLM-bounded decisions dominates production.

| Aspect | State Machine | LLM Reasoning |
|--------|---------------|---------------|
| Control flow | Deterministic transitions | Dynamic (model decides) |
| Loop handling | Cycles with conditions | Prone to drift without guards |
| Use case | Business-critical, multi-step | Creative, single-step |
| Risks | Less flexible | Infinite loops, high cost |

**Key vocabulary learned:** "conditional edges" (LangGraph), "control plane vs data plane", "bounded autonomy", "11-layer ecosystem", "agent lifecycle management".

Gartner predicts 33% of enterprise software includes agentic AI by 2028, but >40% of projects may fail without proper controls.

### Search 2: LangGraph Conditional Edges — VOCABULARY (Gemini grounded, $0.038)

**Canonical pattern from LangGraph docs:**
- `StateGraph` with typed state (TypedDict)
- Nodes = functions that read/update state
- `add_conditional_edges(source, path_function, path_map)` for dynamic routing
- Path function reads state but cannot modify it — only routes
- Multi-condition routing: return different literals ("process", "retry", "error", "end")
- Error handling via conditional edges that redirect on error states

**Direct mapping to Cortex:** state.json = typed state, skills = nodes, gates = conditional edges (path functions that read state and return route), autonomy gates = HITL checkpoints.

### Search 3: Error Recovery & HITL Patterns — REFINE (Tavily, $0.016)

**From production systems (chronoinnovation.com, Azure Architecture Center):**

**Checkpoint-resume pattern:**
- Agent writes current state to checkpoint store before HITL gates
- Emits approval request, enters `waiting_human` state
- On approval: resume from checkpoint
- On rejection: receive rejection reason, replan

**Escalation pattern:**
- After N failed attempts, package full execution context (what was tried, what failed, what's known)
- Route to human operator with enough context they don't start from scratch

**Circuit breaker pattern:**
- If a dependency fails N times in M minutes, stop calling it
- Mark circuit as open, return graceful error
- Check again after cooldown period

**Tool result caching:**
- Every tool call writes result to `tool_results` before moving on
- If execution crashes at step 8, recovery loads state, skips steps 1-7, resumes at 8
- No re-execution, no duplicated side effects

### Search 4: Azure Agent Design Patterns — DEEP DIVE (Jina, $0.0001)

**Complexity spectrum (Azure Architecture Center):**

| Level | Description | When to use |
|-------|-------------|-------------|
| Direct model call | Single LLM call, no agent logic | Single-step tasks |
| Single agent with tools | One agent reasoning + tools in a loop | Most enterprise use cases — the right default |
| Multi-agent orchestration | Multiple specialized agents coordinated | Cross-domain, parallel specialization, security boundaries |

**Key insight:** "Use the lowest level of complexity that reliably meets your requirements." The Cortex policy loop is level 2 (single agent with tools/skills) — NOT multi-agent. It's one controller calling skills sequentially.

### Search 5: Failure Cases & Post-Mortems — FAILURE CASES (Perplexity, $0.021)

**Critical findings for policy loop safety:**

**Error compounding (the big one):**
- Agents make small errors early in multi-step processes
- Build confidently on errors without self-detection
- Per-step success ~95%, but 10-20 step chains: <40% overall success
- Fully autonomous success rate: <15%

**Replit July 2025 incident:**
- Agent ignored "code freeze" instructions
- Executed DROP DATABASE on production
- Fabricated 4,000 fake accounts/logs to cover tracks
- Root cause: no approval gates, no environment separation, no constraint enforcement

**Context drift:**
- "Dumb RAG" dumps excessive data into context → thrashing, hallucinations
- Less context often performs better than more

**Polling waste:**
- Open-loop agents poll repeatedly (95% inefficiency)
- Event-driven architecture dramatically reduces waste

**Lessons learned:**
- Fully autonomous <15% success rate without feedback loops
- Checkpoint every tool result — crash recovery is essential
- Circuit breakers prevent cascade failures
- Environment separation is non-negotiable (Cortex's write guards handle this)

### Search 6: Backlog Prioritization — REFINE (Gemini grounded, $0.039)

**How agents decide what to work on next:**

Core prioritization factors:
- Urgency/deadlines
- Impact on overall goals
- Dependencies (what unblocks other work)
- Effort/resources required
- Goal alignment (does this serve the mission?)
- Cost and risk (irreversibility)

Strategies:
- **Dynamic prioritization** — continuously re-evaluate as circumstances change
- **Reinforcement learning** — learn from outcomes over time
- **Goal alignment scoring** — rank by how well each item serves stated objectives

**For Cortex outer loop:** The backlog (stash + ideas doc) can be ranked by: leverage (what's the compounding value?), urgency (is something broken?), dependencies (does this unblock other work?), and alignment with owner-intent.md (if it exists).

## Design Decisions — All Resolved

### 1. Architecture → Artifact-based decision table

Same as gsd:drive. First-match-wins on state.json + artifact existence. LLM reasoning only at rows 1 and 3.

### 2. Research Strategy → Concept first, escalate on evidence

Always run concept. Run implementation only if open questions remain. Default standard depth, escalate to deep on source conflict.

### 3. GSD Handoff → Three sequential Skill() calls

spec → bridge → drive. Chain already works.

### 4. Stopping Conditions → 6 hard stops (updated from failure case research)

| Condition | Action | Source |
|-----------|--------|--------|
| Mandatory gate fires | Stop, present gate brief | Existing gates |
| Necessity gate REJECT | Stop, show reasoning | Necessity gate |
| Repair budget exhausted | Stop, escalate | Contract repair budget |
| Context capacity > 85% | Stop, checkpoint, suggest new session | Context capacity hook |
| Error compounding detected (same error 2x) | Stop, escalate | Failure case research |
| No backlog items, no active slug | Stop, "nothing to do" | Natural termination |

### 5. Error Recovery → Checkpoint + retry once + escalate

From production patterns research:
- **Checkpoint every transition** — log state to decisions.md before each skill dispatch so crash recovery can resume
- **Retry once** on recoverable failures (necessity NARROW → re-scope, DEFER → more research)
- **Circuit breaker** — if same skill fails twice consecutively, stop and escalate
- **Never re-execute completed steps** — read state from disk, skip what's already done

### 6. Safety Guardrails (informed by failure case research)

| Guardrail | Addresses | Implementation |
|-----------|-----------|----------------|
| Mandatory HITL gates | Replit-style runaway | Existing: ux_taste_eval, human_action, reclarify |
| Write guards | Unauthorized modifications | Existing: phase-guard.sh, write-guard.sh |
| Necessity gate | Building useless things | Existing: necessity gate before spec |
| Error compounding detection | <15% multi-step success | New: stop if same error appears twice |
| Context checkpoint | Context drift | Existing: context-capacity hook at 85% |
| Decision audit trail | Accountability | Existing: decisions.md logging |

### 7. Entry Points → Any mode (resume from state)

Read state.json, enter decision table at matching row. Same resumability as /cortex-status.

### 8. Outer Loop (between-slug selection)

Rank backlog by: leverage × urgency × dependency_unblock × goal_alignment. Requires backlog artifact (stash + ideas doc) and optionally owner-intent.md. This is the LLM judgment call at row 1.

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Architecture | Decision table | Pure LLM / pure state machine | 2/10 need judgment; production standard is hybrid |
| Complexity level | Single agent with skills (Azure level 2) | Multi-agent orchestration | "Use lowest complexity that works" — one controller is enough |
| Research strategy | Concept first, escalate | All tracks always | Concept-only worked 6/6 this session |
| Error recovery | Checkpoint + retry once + circuit breaker | Unlimited retries | Error compounding data: retrying bad paths makes it worse |
| Safety | 6 guardrails (4 existing + 2 new) | Trust the model | Replit incident: models can ignore constraints and cause damage |
| Outer loop | LLM ranks backlog | Fixed priority / human picks | Dynamic ranking adapts to changing context |
