## Summary

The policy loop is a solved problem architecturally. External research confirms the state-of-the-art pattern is a **hybrid state machine with LLM-bounded decisions** — deterministic transitions for the spine, LLM reasoning only at bounded decision points. GSD already implements exactly this pattern in `/gsd:drive` with an artifact-based decision table. The Cortex policy loop should follow the same architecture: read state.json + artifact existence, match against a decision table (first-match-wins), dispatch the next skill. LLM reasoning is needed only for research track selection and depth — everything else is mechanical. The GSD handoff seam is already solved by cortex-bridge. The outer loop (between-slug selection) requires a ranked backlog but is architecturally simple.

## External Research Findings

### Search 1: Agent Orchestration Patterns (Perplexity, $0.0185)

**State of the art (2025-2026):** Hybrid state machine + LLM-bounded decisions.

| Aspect | State Machine | LLM Reasoning |
|--------|---------------|---------------|
| Control flow | Deterministic (explicit transitions) | Dynamic (model decides) |
| Loop handling | Cycles with conditions (retry until met) | Prone to drift without guards |
| Use case | Business-critical, multi-step | Creative, single-step |
| Risks | Less flexible | Infinite loops, high cost |

**Key finding:** LangGraph uses directed graphs as state machines with conditional edges. CrewAI uses supervisor + specialist routing. AutoGen uses conversational multi-agent with orchestration layer. All separate the **control plane** (state/routing/policies) from the **data plane** (tools/execution).

### Search 2: LangGraph Conditional Edges (Perplexity, $0.0237)

**Production pattern for multi-step workflows:**
1. Define typed state (TypedDict tracking messages, results, error_count)
2. Nodes = functions that read/update state (agent, tools, quality check)
3. Conditional edges = routing functions that inspect state and return next node
4. Error recovery = retry loops with state-tracked counters (max retries → escalate)
5. HITL = persistent checkpointers that pause execution and resume on feedback

**Directly maps to Cortex:** state.json = typed state, skills = nodes, gates = conditional edges, autonomy gates = HITL checkpoints.

### Search 3: Stopping Conditions (Perplexity, $0.0179)

**When to stop autonomous loops:**
- Goal completion (objectives fulfilled)
- No actionable state (nothing left to do)
- Budget exhaustion (token/cost limits)
- Persistent failures after retries (escalate to human)
- Context window approaching capacity

**Two-tier guardrails:**
- **Hard hooks:** Framework-level blocks that LLM cannot bypass (budget, compliance, mandatory gates)
- **Soft steering:** Database-driven rules that adjust behavior without failing (context capacity, preferences)

Cortex already has both: mandatory gates (ux_taste_eval, human_action, reclarify) are hard hooks. Autonomy-conditional gates are soft steering.

### Search 4: Claude Agent SDK (Perplexity, $0.0176)

**Anthropic's recommended pattern:**
- SDK handles the tool-use loop (prompt → tool calls → execution → observation → repeat)
- Programmatic control via hooks, permissions, cost limits
- Stateful resumption via file system persistence
- Multi-agent: leader spawns workers, coordinates via custom tools

**Key insight:** The Claude Agent SDK already IS a policy loop for tool execution. The Cortex policy loop sits one level above — it decides which *skill* to invoke, not which tool to call.

## Internal Architecture Findings

### GSD /gsd:drive — The Existence Proof

GSD already has an autonomous orchestrator (`/gsd:drive`) with this exact architecture:

**Decision table (artifact-based, first-match-wins):**

| # | Condition | Action |
|---|-----------|--------|
| 1 | No CONTEXT.md | discuss |
| 2 | Context exists, no RESEARCH.md | research |
| 3 | Context exists, no PLAN.md | plan |
| 4 | Plans exist, not all executed | execute |
| 5 | All plans executed, no UAT | verify |
| 6 | UAT passed | transition (advance phase) |
| 7 | UAT failed, retries < 2 | retry-verify |
| 8 | UAT failed, retries >= 2 | error (stop) |
| 9 | All artifacts exist, phase complete | phase-complete |

**Key design choices in gsd:drive:**
- Always re-read state from disk between iterations (never carry state in memory)
- Use Skill() dispatch, never Agent() (avoids nesting freeze)
- Artifact existence = state (no separate state tracking needed beyond what files exist)
- `_auto_chain_active` flag lets sub-skills know they're being driven

### Cortex State Machine (Derived from This Session)

Mapping the same pattern to Cortex's lifecycle:

| # | Condition | Action | LLM Needed? |
|---|-----------|--------|-------------|
| 1 | state.json slug is null + backlog has items | Pick top backlog item → clarify | Yes (ranking) |
| 2 | mode=clarify, gates.clarify_complete=true | research --phase concept | No |
| 3 | mode=research, research dossier exists, open questions remain | research --phase implementation | Yes (judgment) |
| 4 | mode=research, gates.research_complete=true | spec | No |
| 5 | mode=spec, gates.spec_complete=true, approval=approved | bridge | No |
| 6 | mode=execute, .planning/ exists | /gsd:drive (delegates to GSD) | No (GSD handles) |
| 7 | GSD execution complete, validators exist | Run validators | No |
| 8 | Validators pass | close | No |
| 9 | Validators fail, repair budget > 0 | Repair contract → re-execute | No |
| 10 | Validators fail, repair budget exhausted | Stop, ask human | No |

**Only 2 of 10 transitions need LLM reasoning:**
- Row 1: Picking the next slug from backlog (needs ranking criteria)
- Row 3: Deciding if more research tracks are needed (needs reading the dossier for unresolved questions)

Everything else is a mechanical check on state.json fields and artifact existence.

## Design Decisions — All Resolved

### 1. Architecture → Artifact-based decision table (same as gsd:drive)

**Decision:** First-match-wins decision table based on state.json fields + artifact existence. Same pattern GSD already uses and has proven in production.

**Why not pure LLM reasoning:** Only 2 of 10 transitions need judgment. Making the other 8 LLM calls would add cost, latency, and unpredictability for no value.

**Why not pure state machine:** Research track selection and backlog ranking genuinely need LLM reasoning. A pure state machine can't decide "does this dossier have enough evidence?"

### 2. Research Strategy → Start with concept, escalate only if open questions remain

**Decision:** Always run concept research first. After concept, read the dossier — if open questions remain that are implementation-specific, run implementation. If the clarify brief says complexity=complex, always run implementation. Never auto-run evals track (eval plan is written during spec).

**Evidence:** This session ran concept only for every slug and it was sufficient. Implementation track is needed only when the concept dossier surfaces unresolved implementation questions.

### 3. Research Depth → Standard default, escalate to deep on source conflict

**Decision:** Default to standard depth. Escalate to deep only if the concept dossier contains contradictory findings from different sources that need reconciliation.

**Evidence:** Standard depth was sufficient for all 6 slugs this session. Deep research (gpt-researcher) is expensive and slow — only worth it when sources disagree.

### 4. GSD Handoff → Three sequential Skill() calls

**Decision:** The loop calls `/cortex-spec` → `/cortex-bridge` → `/gsd:drive` in sequence. No new bridge mechanism needed.

**Evidence:** cortex-bridge already reads the exact artifacts cortex-spec produces. gsd:drive already reads the exact artifacts cortex-bridge produces. The chain is already wired.

### 5. Stopping Conditions → 5 hard stops

**Decision:**

| Condition | Action |
|-----------|--------|
| Mandatory gate fires (ux_taste_eval, human_action, reclarify) | Stop, present gate brief, wait for human |
| Necessity gate returns REJECT | Stop, show rejection reasoning |
| Repair budget exhausted (3 repair contracts) | Stop, escalate to human |
| Context capacity > 85% | Stop, save state, suggest new session |
| No backlog items and no active slug | Stop, report "nothing to do" |

### 6. Error Recovery → Retry once, then escalate

**Decision:**
- Research finds nothing → retry with deeper depth (standard → deep)
- Spec necessity gate returns NARROW → re-clarify with narrower scope
- Spec necessity gate returns DEFER → run more research
- Execution fails → GSD's own retry handles it (gsd:drive has VERIFY_RETRIES)
- Any error after one retry → stop and ask human

### 7. Entry Points → Any mode

**Decision:** The loop reads state.json mode and enters the decision table at the matching row. It can resume from any point — mid-research, post-spec, during execution. This is the same resumability pattern Cortex already uses with /cortex-status.

### 8. Observability → decisions.md audit trail + final summary

**Decision:** Every transition logged to decisions.md with timestamp, action, and reasoning. After the loop completes or stops, print a summary of all actions taken.

## Implementation Shape

```python
# cortex-drive.py — simplified pseudocode

while True:
    state = read_state_json()
    artifacts = check_artifact_existence(state.slug)
    
    action = decide_next_action(state, artifacts)  # decision table
    
    if action == 'stop':
        break
    if action == 'ask_human':
        present_gate_brief()
        break
    
    log_decision(action, reasoning)
    dispatch_skill(action)  # Skill() call
    
    # Always re-read state after dispatch
```

**Files:**
- `scripts/cortex/cortex-drive.py` — the policy loop controller
- No new hooks, no new state files, no new skills
- Calls existing skills: cortex-clarify, cortex-research, cortex-spec, cortex-bridge, cortex-close
- Delegates execution to /gsd:drive

**Or:** This could be a new skill `cortex-drive` in `skills/cortex-drive/SKILL.md` that mirrors `/gsd:drive`'s pattern. That's probably cleaner — it's a skill that calls other skills.

## Three-Layer Loop Architecture

| Layer | What it decides | How |
|-------|----------------|-----|
| **Inner loop** (within a slug) | Next lifecycle step | Decision table on state.json + artifacts |
| **Outer loop** (between slugs) | What to build next | Rank backlog by leverage/urgency (LLM judgment) |
| **Feed loop** (generate work) | What ideas to add to backlog | Stash captures, pattern harvest, health report findings, audit findings |

The inner loop is the MVP. The outer and feed loops are extensions.

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Architecture | Artifact-based decision table | Pure LLM / pure state machine | Only 2/10 transitions need judgment |
| Research strategy | Concept first, escalate on evidence | All tracks always / human chooses | This session proved concept-only works for most slugs |
| Research depth | Standard default, deep on conflict | Always deep / always quick | Standard was sufficient 6/6 times; deep is expensive |
| GSD handoff | 3 sequential Skill() calls | New bridge mechanism | Chain already works (spec → bridge → drive) |
| Stopping | 5 hard stops | Configurable thresholds | Hard stops are the minimum safe set |
| Error recovery | Retry once then escalate | Unlimited retries / no retries | Balances resilience with avoiding infinite loops |
| Entry point | Any mode (resume from state) | Beginning only | Matches Cortex's existing resumability model |
| Observability | decisions.md + summary | Real-time dashboard | decisions.md is the existing audit trail |
