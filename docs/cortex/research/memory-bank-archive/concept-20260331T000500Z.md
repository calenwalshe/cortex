## Summary

The Cortex codebase has no terminal lifecycle state. `state.json` cycles through clarify → research → spec → execute → repair indefinitely with no `done` mode, no cold path for completed artifacts, and no close mechanism. The `docs/cortex/archive/` directory does not exist. `decisions.md` is a stub. Every hook and phase-guard either handles `done` gracefully already (session-end, precompact, postcompact, phase-guard) or requires no changes — meaning the entire archive feature can be implemented as a single new `cortex-close` skill plus two minor changes to `scaffold_runtime.sh` and `decisions.md` schema. No existing hooks need modification.

---

## Findings

- `docs/cortex/archive/` does not exist on disk. Must be created; not scaffolded by `scaffold_runtime.sh`.
- `scaffold_runtime.sh` `DOCS_SUBDIRS` array does not include `archive` — new installs will not get the archive directory. Must be added.
- `decisions.md` is currently a stub with zero structured content. It is seeded from `templates/cortex/decisions.md` — that template needs an archive index section added.
- `cortex-phase-guard.sh` falls through to `*) exit 0` for any mode outside clarify/research/spec. The `done` mode is explicitly unblocked — writes to `docs/cortex/archive/` during a close operation are permitted without any guard changes.
- `cortex-session-end.sh` reads `mode` from state.json and writes it verbatim to `current-state.md`. When mode transitions to `done`, it naturally writes "done" to the active surface. No changes needed — the hook is mode-agnostic.
- `cortex-precompact.sh` and `cortex-postcompact.sh` only read slug, mode, and contract for summary generation. They handle any mode value without branching. No changes needed.
- No `cortex-close` skill exists in `skills/`. A new SKILL.md is required.
- The `decisions.md` file is referenced by no hook currently — it is purely a human-readable artifact. The archive index can be appended to it without breaking any automated process.
- All artifact paths in `state.json.artifacts[]` are the canonical set to copy at close time — no other discovery mechanism is needed.
- The phase-guard permits writes to `docs/cortex/` during execute mode (and all post-spec modes). The close operation must require mode to be set to `done` first, or it can set mode = `done` as its first action. Setting mode = `done` as the first action is cleaner — it makes the phase-guard permissive for the close writes and is an atomic declaration of intent.

## Trade-offs

### Option: New `/cortex-close` SKILL.md

**Pros:** Close is a consequential, one-way action — a named command makes its intent explicit and auditable. Consistent with how cortex-clarify, cortex-spec etc. are each separate skills. Easier to require a confirmation step within the skill. Discoverable in the skill surface.
**Cons:** Adds one more skill to install/maintain; adds to the cognitive load of the command surface.
**Verdict:** selected

### Option: `--archive` flag on `/cortex-status`

**Pros:** No new skill to install; piggybacks on an existing entry point.
**Cons:** `cortex-status` is defined as non-destructive and safe to run at any time. Adding a destructive archive action to it violates that contract and will cause confusion. The `--archive` flag would be invisible in the skill surface overview.
**Verdict:** rejected — violates the non-destructive guarantee of cortex-status

### Option: Mirrored archive subdirectory structure (`archive/{slug}/clarify/`, `archive/{slug}/specs/`, etc.)

**Pros:** Archive mirrors the live directory structure exactly — easier to navigate.
**Cons:** More `mkdir -p` commands in the close script; marginally more complex. The archive is cold storage — navigational ergonomics matter less than simplicity.
**Verdict:** selected — mirrors live structure, worth the minor complexity

### Option: Flat archive per slug (`archive/{slug}/` with all files directly)

**Pros:** Simpler copy logic — one `cp -r` per slug.
**Cons:** Loses subdirectory context; a clarify brief and a spec look the same at a glance with no directory signal.
**Verdict:** rejected — mirrored structure is better

### Option: `done` mode set by the human before invoking `/cortex-close`

**Pros:** Explicit human action to signal completion before archive.
**Cons:** Two-step ceremony with no guard to prevent `/cortex-close` being run without `done` mode set. Harder to enforce.
**Verdict:** rejected — `/cortex-close` should set `mode = done` as its first action

### Option: `/cortex-close` sets `mode = done` as its first action

**Pros:** Single command. The mode transition to `done` is the declaration of intent; the archive copy follows immediately. Phase-guard becomes permissive for the writes in the same operation.
**Cons:** If `/cortex-close` fails midway, state.json has `mode = done` but archive may be incomplete. Mitigation: write archive first, then update state.json at the end.
**Verdict:** selected, with mitigation — write archive first, update state.json last

## Recommendations

- Create a new `skills/cortex-close/SKILL.md` implementing the archive lifecycle command
- Add `archive` to `DOCS_SUBDIRS` in `scripts/cortex/scaffold_runtime.sh`
- Add a `## Archive Index` section to `templates/cortex/decisions.md` with a per-entry format: `- {timestamp} | {slug} | closed | contract: {path} | eval-plan: {path}`
- `/cortex-close` execution order: (1) verify done criteria met or prompt user to confirm override, (2) copy all `artifacts[]` paths to `docs/cortex/archive/{slug}/` preserving subdirectory structure, (3) append entry to `decisions.md`, (4) update `state.json` to mode=done, slug=null, active_contract=null, (5) reset `current-state.md` to "not started" state
- Require explicit confirmation: user must type the slug name before archive proceeds — this is a one-way operation
- A slug with no eval-plan at close time should emit a WARNING (not a blocker) — some slugs are docs-only and have no eval obligation
- Do NOT add `/cortex-unarchive` — archive is intentionally one-way; recovery from git history is the unarchive path

## Open Questions

- Should `/cortex-close` check that all done_criteria in the active contract are checked before proceeding, or accept the user's word that it's done?
- The `decisions.md` archive index entry format needs finalisation — what is the minimum set of fields that makes an entry useful 6 months later?
- Should the archive copy also include the fit report (`docs/cortex/fit/{slug}/`) if one exists? It's not in `artifacts[]` currently.
- Should `docs/cortex/archive/` be tracked in git (useful for history) or gitignored (avoids repo bloat)? The artifacts are already committed in their live paths — archiving may create duplicates in git history.
- Does `scaffold_runtime.sh` need to also create the `archive/` subdirectory with a README or `.gitkeep`?
