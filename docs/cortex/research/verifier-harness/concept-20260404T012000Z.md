## Summary

Audited all 14 contracts in the repo. Only 3 have typed validators (21 total: 16 external, 5 judgment). The contract markdown format is consistent and parseable with a simple regex. Prototyped both contract parsing and external validator execution — parser correctly extracts all 21 validators, executor runs all 6 semantic-retrieval externals (100% pass, 0.05-15s per validator). The manifest should be auto-generated from contract markdown on each run (no cached JSON needed). `[judgment]` validators delegate to `cortex-judge.py` via subprocess.

### Contract Parser

Regex: `^- \[.\] \[(external|judgment)\]\s+(.*)` — extracts type and text.
For `[external]`, a second regex extracts the backtick-delimited command and trailing description.

## Design Questions — Resolved

### 1. Manifest format → Auto-generate from contract on each run

**Decision:** No cached `validators.json`. Parse contract markdown at runtime.

**Evidence:**
- Parser is fast (<1ms for any contract)
- Contract is the source of truth — a cached manifest can drift
- 21 validators across all contracts — no scale concern
- Eliminates a sync problem (contract changes require re-gen)

### 2. Parallel execution → No, sequential is fine

**Decision:** Run validators sequentially.

**Evidence:**
- Largest validator set is 8 per contract
- Total execution time for 8 validators: ~17s (acceptable)
- Parallel adds subprocess management complexity for minimal gain
- pytest validators already parallelize internally

### 3. Timeouts → 30s per external, delegate to cortex-judge for judgment

**Decision:** 30-second timeout per `[external]` validator. `[judgment]` validators have their own timeout in `cortex-judge.py` (30s API call).

**Evidence:**
- Slowest observed validator: pytest at 15.4s
- 30s gives 2x headroom over the slowest case
- Judgment validators are API calls — cortex-judge.py already handles timeouts

### 4. Report format → Both JSON (stdout) and markdown (file)

**Decision:** JSON array on stdout (for programmatic use), markdown report at `docs/cortex/evals/{slug}/verify-report.md`.

**Evidence:**
- Matches cortex-judge.py pattern (JSON stdout + markdown report)
- Downstream tools (gate-check, CI) consume JSON
- Humans read the markdown report

### 5. Integration with cortex-judge → Subprocess call

**Decision:** Call `cortex-judge.py run <slug>` as a subprocess for `[judgment]` validators.

**Evidence:**
- cortex-judge.py already handles rubric loading, calibration, API calls, and reporting
- Importing directly would create tight coupling between two independent tools
- Subprocess is the established pattern (hooks call scripts via subprocess)
- cortex-judge.py outputs JSON on stdout — easy to capture and merge

### 6. Partial results → Continue on failure, report all

**Decision:** Run all validators even if earlier ones fail. Report everything.

**Evidence:**
- A single failing validator shouldn't hide other failures
- The report needs complete coverage for the human reviewer
- "Fail fast" makes sense for execution, not for verification

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Manifest | Auto-gen from contract | Cached validators.json | Eliminates drift; parser is instant |
| Execution | Sequential | Parallel | 8 validators in 17s is fine; parallel adds complexity |
| Timeouts | 30s per external | Global timeout / configurable | 2x headroom over slowest case; simple |
| Report | JSON stdout + markdown file | JSON only / markdown only | Matches cortex-judge pattern; serves both machines and humans |
| Judge integration | Subprocess | Direct import | Loose coupling; established pattern |
| Failure mode | Continue all | Fail fast | Complete report is more useful than partial |

## Architecture

```
cortex-verify.py run <slug>
  ├── find contract (docs/cortex/contracts/{slug}/contract-*.md)
  ├── parse [external] and [judgment] validators
  ├── for each [external]:
  │     └── subprocess.run(command, shell=True, timeout=30)
  ├── for each [judgment]:
  │     └── subprocess.run(cortex-judge.py run <slug>)  [once, scores all]
  ├── merge results
  ├── write verify-report.md
  └── output JSON to stdout
```

**Files produced:**
- `scripts/cortex/cortex-verify.py` — the harness CLI
- `docs/cortex/evals/{slug}/verify-report.md` — per-slug verification report

**No new files consumed** — reads existing contract markdown only.
