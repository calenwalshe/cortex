## Executive Summary

Documentation drift is actively happening — 5 hooks undocumented, PostCompact has a .sh/.js mismatch, `cortex-intent` (just shipped) isn't in COMMANDS.md, `reup` skill exists on disk but not in the manifest. The current COMMANDS.md count is already wrong (says 13, should be 14).

The fix: a single `command-registry.json` as the source of truth for command metadata, a `check-doc-drift.sh` that blocks on inconsistencies, and a `generate-docs.js` that regenerates COMMANDS.md from the registry. SKILL.md files stay as-is (no frontmatter needed) — the registry is a separate, parallel metadata file bootstrapped once from current docs.

## Finding 2: SKILL.md Metadata Extraction Assessment

All 14 cortex SKILL.md files were analyzed. Key finding: **no structured metadata exists** — everything is embedded in prose. Section naming is mostly consistent (Arguments, Instructions, Rules, Output Format) but argument formats vary (tables vs bullets vs inline code).

Programmatic extraction from SKILL.md is medium-hard. Rather than adding YAML frontmatter to 14 files, the recommended approach is a **parallel registry file** bootstrapped once from the current COMMANDS.md + manifest.

### What's extractable vs what needs manual mapping

| Field | Extractability | Method |
|-------|---------------|--------|
| Command name | Trivial | Directory name |
| Purpose | Easy | First paragraph after H1 |
| Syntax | Medium | Regex in Arguments section |
| Inputs | Hard | Mixed table/bullet formats |
| Outputs | Hard | Scattered path patterns in prose |
| State effects | Hard | Embedded in "update state" sub-phases |
| Block conditions | Hard | Embedded in conditional prose |

## Finding 3: Design — Registry + Drift Check + Doc Generation

### Architecture

```
SKILL.md files (behavioral source of truth — unchanged)
         ↕ (manual sync)
command-registry.json (metadata source of truth — single JSON file)
         ↓ (automated)
   ┌─────┴─────┐
   ↓            ↓
generate-docs.js    check-doc-drift.sh
   ↓                      ↓
COMMANDS.md          exit 0/1
CORTEX.md count      (PreCommit + CI)
README.md count
```

### command-registry.json — Per-command fields

| Field | Type | Required |
|-------|------|----------|
| name | string | Yes |
| syntax | string | Yes |
| purpose | string | Yes |
| category | spine/validation/utility | Yes |
| profiles | string[] | Yes |
| inputs | array of {name, required, description, values?} | No |
| outputs | array of {artifact, path_pattern, contents_summary} | No |
| state_effects | array of {field, operation, value} | No |
| block_conditions | string[] | No |
| spine_position | int or null | No |
| skill_dir | string | No |

### check-doc-drift.sh — 5-way comparison

| Check | Source A | Source B | Drift type |
|-------|---------|---------|-----------|
| 1 | `skills/cortex-*/` on disk | `runtime-manifest.json` | Missing/extra skill in manifest |
| 2 | manifest cortex-* skills | `command-registry.json` | Missing/extra in registry |
| 3 | registry commands | `docs/COMMANDS.md` H2 headers | Missing/extra in docs |
| 4 | registry count | CORTEX.md + README.md counts | Hardcoded count mismatch |
| 5 | registry skill_dir | `skills/<name>/SKILL.md` on disk | Registry→SKILL.md existence |

Exit 1 on any drift. Runs as PreCommit hook (fast path: skips if no relevant files staged) and in CI.

### generate-docs.js — Fully regenerated COMMANDS.md

- COMMANDS.md becomes **fully generated output** (no hand-edited sections survive)
- Same structure as current: Syntax, Purpose, Inputs table, Outputs table, State Effects table, Block Conditions, Example
- Also updates CORTEX.md "N-Command Surface" heading and README.md "N commands" reference
- Deterministic — no LLM in the path

### Migration path

1. **Bootstrap**: Run extraction script that reads current COMMANDS.md + manifest → populates `command-registry.json`
2. **Verify**: Generate docs from registry, diff against current hand-written docs, iterate until match
3. **Switch**: Replace hand-written docs with generated versions in one atomic commit
4. **Wire**: Add drift check to PreCommit hooks and CI

## Finding 4: Scope Decision — Hooks and Agents

Hooks and agents are **out of scope for the registry** but **in scope for the drift checker**.

Rationale: Hooks and agents aren't user-invocable commands — they don't have syntax, inputs, or block conditions. The manifest already tracks them. But the drift checker should verify that every hook in the manifest has a matching entry in HOOKS.md, and vice versa.

Phase 2 (follow-on): Extend the registry and generator to cover hooks (HOOKS.md) and agents (AGENTS.md) using the same pattern.

## Open Questions Resolved

> "Should the registry be a single JSON file or per-command YAML frontmatter?"
**Answer:** Single JSON file. SKILL.md files have no frontmatter today and don't need it — the registry is a parallel metadata file.

> "Should COMMANDS.md become fully generated?"
**Answer:** Yes. Every section follows the same template. No hand-written prose would be lost.

> "Should the drift check be PreCommit, CI, or both?"
**Answer:** Both. PreCommit catches drift before it reaches the repo. CI is the hard gate.

> "What metadata per command is needed?"
**Answer:** name, syntax, purpose, category, profiles, inputs, outputs, state_effects, block_conditions, spine_position, skill_dir.

> "Should hooks and agents be in the registry?"
**Answer:** Not in phase 1. The drift checker verifies hooks against manifest↔HOOKS.md, but the registry is commands-only.

> "How does this interact with the just-updated COMMANDS.md?"
**Answer:** The hand-written COMMANDS.md becomes the bootstrap source. The registry is extracted from it, then COMMANDS.md is regenerated from the registry. After migration, the hand-written version is replaced.
