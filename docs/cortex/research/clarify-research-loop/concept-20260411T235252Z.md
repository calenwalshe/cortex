# Research Dossier: clarify-research-loop — concept

**Slug:** clarify-research-loop
**Phase:** concept
**Timestamp:** 20260411T235252Z
**Depth:** standard

---

## Summary

The Cortex discovery loop is **already designed and shipped** — `docs/DISCOVERY_LOOP.md`, the `cortex-discovery-loop` slug closed 2026-04-01, `reclarify_required` field in state.json, mandatory `reclarify` gate in `/cortex-spec`, `cortex-experiment` skill, and a structured uncertainty register in `open-questions.md` with five fields (type/severity/resolution_path/status/resolved_by). **But it has never fired in practice.** Zero state.json files have ever set `reclarify_required: true`, the `docs/cortex/experiments/` directory does not exist, no slug has ever invoked `/cortex-experiment`, and no decisions.md entry references either gate firing. The mechanism is dormant because the `/cortex-research` SKILL describes the trigger as a soft prose instruction ("evaluate whether the research evidence contradicts or materially changes the problem frame") with no concrete signal definition, no checklist, no LLM-evaluator step — so the running model finishes a dossier, internally judges "looks fine," and never trips the flag. The right work is **not** building a convergence loop; it's **operationalizing the existing one** by making the trigger criteria concrete, observable, and hard for the LLM to skip.

---

## Findings

- **Cortex already has a discovery loop spec.** `docs/DISCOVERY_LOOP.md` is the authoritative design doc, produced by the `cortex-discovery-loop` slug (closed 2026-04-01). It defines 8 valid modes (clarify/research/experiment/spec/execute/validate/repair/assure), explicit transition triggers, the `reclarify_required` field semantics, and 6 convergence guardrails drawn from HDD/Lean/Shape Up.
- **Three spec-readiness blockers exist in `/cortex-spec`** and are wired as MANDATORY gates that cannot be disabled by autonomy preset: (1) `reclarify_required: false`, (2) no critical open uncertainties, (3) every core assumption backed by evidence. Source: `.claude/skills/cortex-spec/SKILL.md` lines 41-75.
- **`/cortex-research` Phase 4 already specifies the reclarify trigger** but as a single soft sentence: *"evaluate whether the research evidence contradicts or materially changes the problem frame or core assumptions established in the clarify brief."* No checklist, no concrete signals, no separate evaluator LLM call, no diff against the brief. The instruction sits at the bottom of a long SKILL where it is easy to skip.
- **The trigger has never fired.** Zero git commits set `reclarify_required: true` in any state.json. Zero archived slugs reference reclarify being triggered. Zero decisions.md entries log a reclarify event. The `experiments/` directory does not exist on disk for any slug. The cortex-experiment skill exists but has been invoked zero times in decisions.md history.
- **The structured uncertainty register exists but is unused.** `docs/cortex/handoffs/open-questions.md` defines a 5-field schema (type/severity/resolution_path/status/resolved_by) cross-referenced from DISCOVERY_LOOP.md §3, but the current file is empty (no active slug). Past clarify briefs and dossiers do not populate it — they list questions in prose form.
- **Shape Up (Basecamp) treats shaping and betting as separate explicit commitments.** Per Nathan Baschez's analysis: shaping is exploratory, time-bounded, and produces a pitch; the betting table is the commitment moment. Convergence in shaping is enforced by **fixed appetite** (timebox), not by quality judgment. "Commit to the smallest unit of incremental work that reduces uncertainty meaningfully."
- **Niko Matsakis's staged RFC proposal (Rust)** uses explicit stages with promotion criteria — Pre-RFC (spitballing) → RFC (designing) → implementation → call for feedback → stabilization. The move from spitballing to designing requires a **named team champion plus general team agreement** as a hard gate, not a quality judgment. Influenced by TC39 stages 0-4.
- **Phil Calcado's structured RFC process** makes a stronger claim: feedback is *informational* — the author is free to incorporate or reject it, but must **acknowledge every piece**. Convergence is not consensus; it's exhausting the structured-acknowledgement loop and reaching an explicit decision moment.
- **Numerical methods literature on iterative stopping criteria** (per Perplexity comparison): max iteration cap and delta threshold (Δ < ε between iterations) dominate. Real teams typically combine cap + delta. Confidence-based stopping is computationally expensive. Software/RFC contexts under-use formal stopping criteria — they tend toward implicit human-judgment stops, which is exactly the failure mode this slug is reacting to.

## Trade-offs

### Option: New `/cortex-converge` skill between research and spec
**Pros:** Single concrete chokepoint; easy to discover; explicit invocation creates an artifact (convergence-check.md) the human can read; clean separation of concerns from existing skills.
**Cons:** Adds another step to remember; one more skill in the surface; risks duplication with existing `/cortex-spec` blockers; may invite skipping ("I know it's converged, just spec it").
**Verdict:** deferred — only attractive if the existing in-skill gate cannot be made to trigger reliably.

### Option: Make `/cortex-research` Phase 4 trigger concrete via checklist
**Pros:** Operationalizes a mechanism that's already wired and gated; no new surface area; lowest-cost change; preserves the existing `/cortex-spec` blocker; the LLM running research has fresh dossier context, which is exactly the right moment to judge frame validity.
**Cons:** Still LLM-as-judge; checklist items can be answered "no" by inattention; doesn't create a separate evaluator persona to push back on the synthesizer.
**Verdict:** selected (provisionally — see recommendation 1).

### Option: Force a separate evaluator LLM call at end of `/cortex-research`
**Pros:** Splits "synthesize findings" from "judge whether frame is still valid" into two LLM calls with different prompts — same Generator/Evaluator pattern already used in `--agentic` mode (Phase 2.7); harder to skip than a single soft instruction; explicit JSON output schema prevents drift.
**Cons:** Adds one LLM call per research run (~--phase01-.04 cost); adds complexity to the skill; may produce false positives if evaluator is too aggressive (defeating the loop by re-clarifying when not needed).
**Verdict:** selected as the primary mechanism.

### Option: Stopping criterion = max iterations
**Pros:** Dead simple; predictable cost; matches numerical-methods practice.
**Cons:** Ignores actual convergence; can stop prematurely or waste iterations; arbitrary number invites argument; the hard problem isn't *how many* loops, it's *whether to enter one at all*.
**Verdict:** rejected as primary criterion. Use as a circuit-breaker only (e.g., max 3 reclarify cycles per slug).

### Option: Stopping criterion = delta threshold (questions answered this pass / new questions opened)
**Pros:** Tracks actual learning; reuses existing question-classification structure (5-type taxonomy); produces an auditable per-pass delta in the dossier.
**Cons:** Requires maintaining the structured uncertainty register (currently unused); LLM may invent or overlook questions, biasing the delta; threshold value is arbitrary.
**Verdict:** selected as the primary stopping signal — combined with the max-iterations circuit breaker.

### Option: Stopping criterion = fixed appetite/timebox (Shape Up style)
**Pros:** Forces commitment; aligns with the existing `cortex-experiment` learning-contract `Appetite/Timebox <!-- REQUIRED -->` field; matches Basecamp's empirical track record.
**Cons:** Cortex slugs are not currently appetite-bounded at the clarify stage; would require adding an appetite field to the clarify brief; harder to enforce in an LLM workflow than in a human-team workflow.
**Verdict:** deferred to a future slug — out of scope for operationalizing the existing loop.

## Recommendations

- **Reframe this slug from "build a convergence loop" to "operationalize the existing dormant one."** The DISCOVERY_LOOP.md design is sound and complete; the failure is purely in the trigger criteria being soft prose instead of a structured check. Update the clarify brief to reflect this reframing in the next pass.
- **Add a dedicated Reframe-Check evaluator step at the end of `/cortex-research` Phase 4.** Run a separate LLM call with a skeptical-evaluator prompt (parallel to the `--agentic` Evaluator persona, but mandatory not opt-in). Inputs: the new dossier + the original clarify brief Goal/Constraints/Assumptions sections. Output: structured JSON `{reframe_required: bool, invalidated_assumptions: [], new_constraints: [], scope_delta: str, confidence: float}`. If `reframe_required: true`, write `reclarify_required: true` to state.json and emit the existing RECLARIFY REQUIRED warning.
- **Define the concrete signals that justify `reframe_required: true`.** From the brief's q2 and the DISCOVERY_LOOP.md text: (a) an assumption listed in the brief is contradicted by a finding; (b) a new hard constraint emerges that the brief's Constraints section did not name; (c) the Goal sentence as written is now incoherent with the dossier; (d) a non-goal turns out to be a required goal or vice versa. Ship these as a checklist the evaluator must fill in.
- **Stopping criteria: combine max iterations + delta threshold.** Hard cap at 3 reclarify cycles per slug (after the third, the slug must either spec or be archived). Delta threshold: if a pass produces no new findings that change any of the 4 concrete signals above, the loop converges and the next call to `/cortex-spec` is unblocked. Both criteria must be auditable in `decisions.md` — each cycle appends an entry recording cycle number, delta, and converge/continue verdict.
- **Activate the structured uncertainty register.** The 5-field schema in `open-questions.md` is already specified but unused. Have `/cortex-clarify` populate it from the brief's Open Questions (mapping to type/severity/resolution_path) and have `/cortex-research` update `status` and `resolved_by` per question. This is the substrate the delta threshold operates on.
- **Do not build a `/cortex-converge` skill yet.** Adding new surface is the wrong fix when the existing surface has a dormant gate. Prefer making the dormant gate trigger reliably first; if after 5 slugs the rate of "should-have-reframed but didn't" is still high, then add an explicit skill.
- **Do not extend `cortex-experiment` in this slug.** The experiment subsystem also exists and is unused, but its activation is a separate concern (different trigger, different artifacts) — bundling would reproduce the original mistake of trying to do too much at once.

## Adjacent Findings

- **Niko Matsakis's staged RFC promotion gate is a named team champion + team agreement, not a quality judgment.** Cortex's analog is the human approver — but Cortex currently has no equivalent of "named champion" forcing function at the research → spec boundary. If reclarify never fires, the human-approval moment becomes the de-facto convergence gate, which makes it the only place where reframing actually happens. Why this matters: if the evaluator step proposed in recommendation 2 doesn't trip in practice either, the fallback is to make the human-approval gate ask explicit "did anything in research invalidate the brief?" rather than implicit "approve this contract?" Source: https://smallcultfollowing.com/babysteps/blog/2018/06/20/proposal-for-a-staged-rfc-process/

- **Shape Up uses fixed appetite as the convergence enforcer, not quality judgment.** Basecamp's empirical observation is that quality-based stopping is unstable; teams oscillate or never converge. Time-bounded shaping forces commitment with whatever clarity exists at the deadline. Why this matters: Cortex clarify briefs do not currently have an appetite/timebox field. If the evaluator + delta-threshold combo fails to bound the loop, adding an appetite field (parallel to the one already mandatory in `learning-contract.md` for experiments) is the proven fallback. Source: https://basecamp.com/shapeup/shape-up.pdf

## Open Questions

- Should the Reframe-Check evaluator be a new dedicated agent (like `cortex-critic`), an inline LLM call inside `/cortex-research`, or a phase inside `/cortex-spec` that runs before the existing 3 blockers? (Tradeoff: dedicated agent = clearest separation, inline = lowest friction, in-spec = closest to the gate that actually blocks.)
- What is the right confidence threshold for the evaluator's `reframe_required` output? A boolean is brittle; a 0.0-1.0 score with a configurable threshold is more flexible but invites gaming.
- Is the structured uncertainty register the right substrate for the delta threshold, or should the delta operate on something else (e.g., diff between current dossier findings and prior dossier findings if a slug has multiple research passes)?
- Does the existing 5-type question taxonomy need extension to mark which questions are "frame-relevant" vs "implementation-detail"? Only frame-relevant questions should drive reframe_required.
- Should this slug also retroactively audit a sample of closed slugs (e.g., 5-10 most recent) to count how many *should* have reframed but didn't? This would produce a baseline metric for measuring whether the operationalization actually moves the needle.
- How should the spec for this work treat the `cortex-experiment` skill — leave it untouched (separate concern), or add a recommendation that the same kind of operationalization is needed there too?
