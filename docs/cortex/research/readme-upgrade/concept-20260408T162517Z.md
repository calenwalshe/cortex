## Summary

The README is structurally sound but has 11 specific content gaps where the system has outgrown the documentation. The command table is missing 2 commands (`/cortex-intent`, `/cortex-ship`), the structure tree is stale (missing 7+ entries), and several major subsystems (autonomy, agents, hooks, knowledge engine, experiment mode, owner intent) have zero representation. The fix is a targeted content refresh within the existing section structure — no narrative rewrite needed.

---

## Findings

- **Command table lists 14 rows, should list 16.** Missing: `/cortex-intent` (owner alignment layer) and `/cortex-ship` (push + PR creation). `/cortex-parallel` is present. All 16 skills have SKILL.md files in `skills/`.
- **command-registry.json lists 15 commands** (missing `cortex-parallel`). The README and registry are independently incomplete — both need sync.
- **Structure tree is stale.** Missing from tree: `docs/DISCOVERY_LOOP.md`, `docs/HOOKS.md`, `docs/index.html`, `command-registry.json`, `config/` directory. Skills tree only shows 10 of 20 skill dirs (missing experiment, close, fit, stash, drive, parallel, ship, intent, reup). `.claude/hooks/` shows only 3 categories but there are 20 hook scripts.
- **4 specialized agents exist with zero README mention.** `cortex-critic` (adversarial review), `cortex-eval-designer` (eval matrix), `cortex-scribe` (continuity), `cortex-specifier` (spec compression). Each has role-based write scopes enforced by hooks.
- **20 hook scripts wired to Claude Code events** — session lifecycle (start/end/compact), phase guard, write guard, research guard, task gating, token ledger, doc sync, context capacity, validator trigger, teammate idle, distribute, supervisor log. README just says "Hook scripts (session lifecycle, phase guard, task gating)."
- **Autonomy system has zero README presence.** 13 configurable gates, 4-layer resolution (invocation > project > global > preset), 3 presets (supervised/gates-only/full-auto), `--dry-run` on all commands, mandatory gates that override config. This is a major feature for autonomous operation.
- **Knowledge engine (`.cortex/facts.jsonl`) not mentioned.** Cross-slug lesson persistence — observations and lessons from prior work inform future research.
- **Owner intent layer not mentioned.** `docs/cortex/intent/owner-intent.md` provides mission, objectives, non-negotiables, tradeoff preferences, kill criteria. Auto-injected into every clarify brief as standing constraints.
- **Complexity tiers not mentioned.** Trivial/standard/complex routing — trivial skips research, complex forces deep research. Affects pipeline depth.
- **Repair loop semantics not mentioned.** Bounded repair with convergence stall detection, circuit breaker (2 consecutive failures), never backtracks past spec.
- **Adjacent discovery not mentioned.** IC Outside-In domain analysis, assumption-indicator generation (I&W), 6-stage VOI filter pipeline — this is the system's intelligence differentiator.

## Trade-offs

### Option: Full content refresh (update every section in place)
**Pros:** Accurate, no structural changes, minimal diff for existing users
**Cons:** Some sections (structure tree) need significant expansion
**Verdict:** selected

### Option: Add new sections for agents, autonomy, hooks
**Pros:** Gives proper visibility to major subsystems
**Cons:** README grows longer; risk of becoming a manual
**Verdict:** selected — but each new section should be 5-10 lines max with a pointer to docs/

### Option: Collapse into a shorter README + separate FEATURES.md
**Pros:** Keeps README minimal
**Cons:** Splits the entry point; new users would miss features
**Verdict:** rejected — keep single README, use doc pointers for depth
