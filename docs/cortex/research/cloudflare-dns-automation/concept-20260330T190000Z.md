# Research Dossier — Cloudflare DNS Automation

**Topic:** How to get a Cloudflare API token for DNS automation and let Claude Code administer DNS records programmatically.
**Method:** Perplexity sonar-pro

---

## Summary

Two credentials needed: an **API Token** (scoped to Zone:DNS:Edit on calenwalshe.com) and the **Zone ID** for the domain. Both take ~3 minutes to obtain from the Cloudflare dashboard. Once in `~/agent-stack/.env`, Claude Code can create, update, and delete DNS records via the Cloudflare REST API with no manual steps.

---

## Step 1 — Create the API Token (do this manually once)

1. Go to [dash.cloudflare.com](https://dash.cloudflare.com)
2. Profile icon (top-right) → **My Profile** → **API Tokens** (left sidebar)
3. **Create Token** → select the **"Edit zone DNS"** template
4. Under **Zone Resources**: Include → Specific zone → `calenwalshe.com`
5. (Optional but useful) Add **Zone:Zone:Read** permission — lets Claude Code look up Zone ID programmatically later
6. **Continue to summary** → **Create Token**
7. Copy the token immediately — it's only shown once

> Use **API Token**, not Global API Key. Token is scoped to one zone; Global Key exposes your entire account.

---

## Step 2 — Get the Zone ID (do this manually once)

1. Cloudflare dashboard → click **calenwalshe.com**
2. Right sidebar → copy the **Zone ID** (32-char hex string)

---

## Step 3 — Add to .env

```bash
# ~/agent-stack/.env
CLOUDFLARE_API_TOKEN=your_token_here
CLOUDFLARE_ZONE_ID=your_zone_id_here
CLOUDFLARE_SERVER_IP=144.202.81.218
```

---

## What Claude Code can then do automatically

Every new subdomain becomes a single API call:

```bash
# Create A record for docs.calenwalshe.com
curl -s -X POST "https://api.cloudflare.com/client/v4/zones/$CLOUDFLARE_ZONE_ID/dns_records" \
  -H "Authorization: Bearer $CLOUDFLARE_API_TOKEN" \
  -H "Content-Type: application/json" \
  --data "{\"type\":\"A\",\"name\":\"docs\",\"content\":\"$CLOUDFLARE_SERVER_IP\",\"proxied\":true}"
```

Full automation sequence for any new service:
1. Cloudflare API → create DNS A record
2. Append Caddyfile block
3. `docker compose up -d new-service`
4. `docker compose exec caddy caddy reload`

Zero manual steps after initial credential setup.

---

## Recommendations

- Add `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_SERVER_IP` to `~/agent-stack/.env`
- Scope the token to `calenwalshe.com` only with Zone:DNS:Edit + Zone:Zone:Read
- No expiry needed (this is an admin automation token) — but keep it in `.env` which is gitignored
