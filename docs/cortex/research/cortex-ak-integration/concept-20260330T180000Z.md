# Research Dossier — Cortex AK Integration (v1.1 Candidate)

**Topic:** Six proposed cortex updates — AK-lite kernel, post-edit auto-verify, model convergence overlay, memory archive, research coordinator, uniform quick variants.
**Method:** Codebase analysis (hooks, layers, skills, manifest) cross-referenced against proposals.

---

## Summary

All six proposals are architecturally sound fits for cortex. None require new commands or structural changes to the layer model. The highest-priority item by practical impact is **#2 (post-edit auto-verify)** — the scaffold already exists and the delta is small. The highest-effort item is **#1 (AK kernel)** because it requires changes to every skill and the CLAUDE.md.snippet. **#4 (archive)** and **#6 (quick variants)** are low-risk additive changes. **#3 (convergence)** and **#5 (coordinator)** are medium-effort upgrades to existing opt-in mechanisms.

### 1. AK-lite Reasoning Kernel

**What exists:**

`layers/thinking/` has four files: `anti-sycophancy.md`, `forcing-questions.md`, `investigate.md`, `security-audit.md`. These are behavioral rules — they suppress bad output patterns (sycophancy, fake certainty) but they are not a sequential reasoning flow. `CLAUDE.md.snippet` wires them as "always active" via the Layer 3 description, but it does so by listing rule categories, not by encoding a phase sequence the model follows.

The skills (clarify, research, spec, review) each have their own multi-phase instruction sets. None reference a shared kernel. Clarify → Research → Spec → Review is a workflow sequence, but there is no embedded per-skill reasoning loop that mirrors attune→shape→make→refine.

**Delta:**

A 4-phase reasoning kernel needs to be written as a new `layers/thinking/reasoning-kernel.md` (or inline in CLAUDE.md.snippet), then referenced in the preamble of each relevant SKILL.md. The mapping the proposal defines is correct:

| AK phase | Cortex binding |
|----------|----------------|
| attune   | clarify — understand the problem before framing it |
| shape    | research + spec — structure the intelligence into a form |
| make     | GSD execution boundary (cortex does not own this) |
| refine   | review + audit + evals + repair |

The kernel should be ~200 words in the thinking layer: what each phase means, when to apply it, and the single forcing question for each phase. It is referenced by name in SKILL.md preambles — not duplicated.

**Risks:**

1. **Prompt inflation.** Each SKILL.md that references the kernel adds loading overhead. Keep the kernel tight (≤250 words) and reference it by name/path rather than inlining.
2. **Make boundary.** Cortex must not blur into GSD execution. The kernel's "make" phase should be defined as an explicit handoff point ("produce the GSD handoff artifact and stop"), not as an instruction to execute.
3. **Activation gap.** Layers in `layers/` are not automatically loaded — they only activate if the CLAUDE.md.snippet references them or the user's global config does. Wiring the kernel through CLAUDE.md.snippet (not just layers/) is the safe path.

### 2. Real Post-Edit Auto-Verify

**What exists:**

This is the most scaffolded proposal. The infrastructure is ~70% there:

- `cortex-validator-trigger.sh` — PostToolUse hook, fires async on Write|Edit during execute/repair mode, appends to `.cortex/dirty-files.json`. Comment in the hook explicitly notes: "Does NOT run validators inline."
- `cortex-task-completed.sh` — TaskCompleted hook, reads `docs/cortex/handoffs/eval-status.md`, blocks completion if any `| FAIL` lines present or if eval-status.md is absent.
- `.cortex/dirty-files.json` — schema exists and is populated.
- `.cortex/validator-results.json` — mentioned in proposal; does NOT currently exist (no schema, no write path).

**Delta:**

`cortex-validator-trigger.sh` needs one new block after the dirty-file append:

1. Look up the fast verifier command. Check in order: `package.json` script `cortex:verify:fast` → `Makefile` target `cortex-verify-fast` → `.cortex/verify.sh` fallback. If none found, skip and write a "no verifier configured" entry to eval-status.md.
2. Run the verifier (background/async is fine — PostToolUse is already async).
3. Write results to `.cortex/validator-results.json` (structured: `{file, command, exit_code, output, timestamp}`).
4. Refresh `docs/cortex/handoffs/eval-status.md` — one row per validator, PASS/FAIL/SKIP.

The TaskCompleted hook already blocks on FAIL in eval-status.md — no changes needed there.

**Risks:**

1. **Async timing.** PostToolUse is async — the validator runs after the write but may finish after the task is marked complete. The TaskCompleted hook's "no eval-status.md" block is the safety net. If the validator is still running when TaskCompleted fires, it blocks. This is correct behavior, not a bug.
2. **Verifier output size.** Large test output in validator-results.json could grow unbounded. Cap stored output at 500 lines and write a truncation notice.
3. **False negatives on missing config.** If no verifier is configured, silently skipping means the gate never fires. The "no verifier configured" entry in eval-status.md should be `SKIP` not `PASS` — so the gate doesn't silently approve unverified work.

### 3. Model Convergence Overlay

**What exists:**

- `cortex-critic` agent — adversarial reviewer, invoked by `/cortex-review` or directly. Reads spec/contract, finds logical gaps, does NOT propose fixes.
- `cortex-eval-designer` agent — proposes eval suites from spec and contract.
- `cortex-specifier` agent — drafts specs from research dossiers.
- `--team` flag on `/cortex-research` — exists in the skill signature; invokes an agent team (exact orchestration not yet explicit — see proposal #5).

There is no current pattern for "run multiple independent model reads on a high-stakes artifact as a gate before approval." The critic is invoked explicitly, not automatically.

**Delta:**

Add a `--converge` flag (or make it part of approval gate) for:
- `/cortex-spec` — after writing spec.md, before updating state to approval-pending, optionally invoke cortex-critic and a second synthesis pass
- `/cortex-research --phase evals` — after writing eval-proposal.md, run critic pass before surfacing to user for approval
- `/cortex-audit --comprehensive` — run second-opinion synthesis after full audit

The cleanest implementation is a shared `converge()` pattern in the skill instructions: "If `--converge` flag is set OR artifact type is in `{spec, eval-proposal, audit-report}`: invoke cortex-critic agent on the artifact before surfacing approval prompt." The critic's output appends to the artifact as a `## Critic Review` section.

**Risks:**

1. **Cost and latency.** Every convergence call spawns an agent. Gate this behind an explicit flag for all commands except audit --comprehensive (where it should be default).
2. **Critic paralysis.** If the critic always finds something, convergence becomes a blocking loop. The critic must produce findings with severity — only CRITICAL or HIGH findings block; others are advisory.
3. **Model homogeneity.** If the critic runs on the same model as the spec author, "convergence" is just self-review. For genuine second opinion, the critic agent should be configured to use a different model (e.g., Opus when spec was written by Sonnet). This requires model routing in the agent definition — currently not in cortex-critic.md spec.

### 4. Memory-Bank Archive / Curation

**What exists:**

Continuity artifacts: `docs/cortex/handoffs/current-state.md`, `docs/cortex/handoffs/decisions.md` (referenced but content not verified), `docs/cortex/handoffs/eval-status.md`. Compaction snapshots via `cortex-precompact.sh` and `cortex-postcompact.sh`. Session end via `cortex-session-end.sh`.

No `docs/cortex/archive/` path. No contract-close event or explicit done→archive transition. Long-running projects will accumulate handoff artifacts for every slug with no rotation.

**Delta:**

Three additions, all additive (no existing behavior changes):

1. **Archive path:** `docs/cortex/archive/{slug}/` — copy of slug's clarify brief, research dossiers, spec, contract, eval results, and final current-state snapshot at contract-close time.
2. **Archive index:** Add an `## Archive` section to `docs/cortex/handoffs/decisions.md` — one line per archived slug: date, slug, outcome summary.
3. **Archive trigger:** Add an optional `archive` step to `/cortex-status` output ("slug X is in done state — run `/cortex-status --archive` to archive and clear active context"). Add an explicit `cortex-archive` step invokable from cortex-spec or via a future `/cortex-close` command.

**Risks:**

1. **Archive vs. delete confusion.** Archive should copy, not move. The source artifacts stay in place for reference — only the "active" surface (current-state.md) gets cleared.
2. **When is "done"?** Currently there is no explicit contract-close event. The archive trigger needs a clear definition: done = `state.json.mode == "done"` OR all done_criteria in the contract are checked. Define this before implementation.
3. **Low risk overall.** This is the cleanest proposal — purely additive, no hook or skill changes required for v1.

### 5. Research Coordinator under --team

**What exists:**

`--team` flag exists in the cortex-research skill signature. The manifest lists `cortex-critic.md` and `cortex-eval-designer.md` as agents. The current `--team` implementation in the skill instructions is not fully specified — the SKILL.md says "invokes agent team for research (opt-in, adds cost)" but the Phase 2 instructions don't branch on `--team` with explicit orchestration logic.

**Delta:**

Define explicit `--team` orchestration for each research phase:

| Phase | Coordinator | Workers | Synthesizer |
|-------|-------------|---------|-------------|
| concept | Coordinator agent fans out 3 parallel searches (market, prior art, analogues) | 3 search subagents | Coordinator synthesizes + flags conflicts |
| implementation | Adversarial split — one agent argues for the proposed approach, one argues against | 2 adversarial subagents | Coordinator adjudicates |
| evals | critic + eval-designer pair | cortex-critic + cortex-eval-designer | Coordinator resolves dimension conflicts |

This is an upgrade to the `--team` branch in Phase 2 of the research skill — not a new command, not a new agent type.

**Risks:**

1. **Cost.** Three agents per concept research pass is 3x the token cost. Gate clearly behind `--team` and display a cost warning before spawning.
2. **Coordinator identity.** Who is the coordinator? Currently no `cortex-coordinator` agent definition. Either the main Claude session acts as coordinator (running subagents and synthesizing), or a dedicated coordinator agent is defined. The simpler path is main-session-as-coordinator — avoids adding another agent definition.
3. **Non-fit boundary.** The proposal is explicit: do not extend `--team` semantics to build execution. This must be enforced in the SKILL.md — `--team` activates only during research mode, not execute or repair.

### 6. Uniform Quick Variants

**What exists:**

- `--depth quick|standard|deep` on `/cortex-research`
- `--quick` on `/cortex-audit`
- No depth/effort tier on: cortex-clarify, cortex-spec, cortex-review, cortex-investigate, cortex-status

The pattern is inconsistent — research uses `--depth quick`, audit uses `--quick`. These should be unified.

**Delta:**

Standardize on `--depth quick|standard|deep` across all commands. For commands that currently have no tier, define what each level drops:

| Command | quick drops | standard | deep adds |
|---------|-------------|----------|-----------|
| cortex-clarify | open questions expansion, next-research-steps list | current behavior | extra clarifying Q&A round |
| cortex-spec | alternatives considered, risks section | current behavior | full convergence pass (see #3) |
| cortex-review | security lens | engineering lens only | + convergence pass |
| cortex-investigate | pattern analysis phase | current behavior | multi-session persistence |
| cortex-audit | alias for existing `--quick` | current | full STRIDE + OWASP |
| cortex-research | already has this | already has this | already has this |

Migrate `cortex-audit --quick` to be an alias for `cortex-audit --depth quick` for consistency.

**Risks:**

1. **Quick spec risk.** A spec without a risks section or alternatives considered is a genuine quality loss. `--depth quick` on cortex-spec should emit a visible warning: "Skipping risks and alternatives — this spec is not safe for high-stakes contracts."
2. **Flag name collision.** cortex-audit already has `--quick`. Renaming it to `--depth quick` is a breaking change for anyone using it. Add `--quick` as a permanent alias and mark it deprecated in the skill.
3. **Minimal implementation effort.** Each skill needs one branch on `--depth` argument. The total delta across all skills is ~50 lines of instruction text — this is the easiest proposal to ship.

## Trade-offs

| Proposal | Effort | Impact | Risk |
|----------|--------|--------|------|
| #1 AK kernel | Medium | Medium — improves reasoning consistency | Low if kernel stays tight; medium if it inflates prompts |
| #2 Post-edit verify | Low | High — closes the only real execution gap vs. Fuente | Low — scaffold already exists |
| #3 Convergence overlay | Medium | High for high-stakes artifacts | Medium — model routing needed for genuine second opinion |
| #4 Archive | Low | Medium — prevents artifact rot | Very low |
| #5 Coordinator | Medium | Medium — improves team research quality | Medium — cost and coordinator identity |
| #6 Quick variants | Low | Medium — usability across command surface | Low — backward-compat alias for audit --quick |

---

## Recommendations

**Ship in this order:**

1. **#2 first.** One hook change, no skill changes, highest practical payoff. Closes the testing/assurance gap immediately.
2. **#6 second.** Pure instruction changes across skills. Low effort, immediately visible consistency improvement.
3. **#4 third.** Additive path and index. Zero risk, good housekeeping before the next milestone.
4. **#1 fourth.** Write the kernel, wire it into skills one at a time. Start with cortex-clarify and cortex-spec where the attune/shape phases are most load-bearing.
5. **#3 fifth.** Requires model routing decision. Block until that architectural choice is made (same model = not real convergence).
6. **#5 last.** Requires coordinator pattern definition. Most design work of the six.

**Open questions before speccing:**

- #2: What is the fallback when no verifier is configured — SKIP (silent pass-through) or WARN (advisory, non-blocking)?
- #3: Should cortex-critic run on a different model by default, or is same-model review acceptable for v1?
- #3: Is `--converge` a flag or a mode in state.json?
- #5: Main-session-as-coordinator vs. dedicated cortex-coordinator agent — which fits the existing agent pattern better?
