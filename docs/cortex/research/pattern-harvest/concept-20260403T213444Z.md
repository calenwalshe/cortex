## Summary

Across 10+ competing systems (BMAD, LangGraph, CrewAI, Pydantic AI, Google ADK, Roo Code, Praetorian, Swarm-IOSM, OpenHands, Mem0, DeepEval, MemGPT), we identified 20 concrete patterns compatible with Cortex's artifact-driven architecture. They cluster into 4 tiers: safety nets (prevent runaway loops and silent degradation), repair quality (make each fix attempt count), intelligence depth (better evals and memory), and routing sophistication (smarter task classification). Cortex's core architecture — artifact pipeline + contract gates + GSD execution — is validated as the winning topology. No system combines all of what Cortex has. The gaps are at the edges: convergence detection, token-efficient memory retrieval, complexity-adaptive planning, and repair budgets.

## Findings by Category

### A. Safety Nets (Prevent Infinite Loops + Silent Degradation)

**1. Convergence detector with similarity scoring**
- Source: Praetorian, OpenClaw, Ralph Loop
- Pattern: After each repair-verify cycle, compare current failure signature to previous N failures. If >80% similar for 3+ cycles, declare CONVERGENCE STALL and escalate instead of looping.
- Cortex gap: Repair loop has no convergence detection — can spin indefinitely
- Effort: Small — add to cortex-review's repair recommendation logic

**2. Repair budget + cooldown**
- Source: Swarm-IOSM, self-healing systems
- Pattern: `max_repair_contracts: 3`, `cooldown_between_repairs: 300s`. On budget exhaustion, escalate to human instead of creating contract-004.
- Cortex gap: No repair iteration cap or cooldown
- Effort: Small — new fields in contract template, checked by cortex-spec

**3. Context capacity gate**
- Source: Praetorian
- Pattern: Gate execution at <75% context (proceed), 75-85% (warn), >85% (hard block — run /compact). Prevents silent quality degradation from context overflow.
- Cortex gap: No context-capacity gate. Long contracts silently degrade.
- Effort: Small — new mandatory gate + PostToolUse hook reading remaining_percentage

**4. Circuit breaker for Codex dispatch**
- Source: Multi-agent failure playbook, self-healing systems
- Pattern: Track consecutive Codex failures per wave. After 3 failures, route all remaining tasks to Claude for the rest of the phase.
- Cortex gap: Each Codex failure is handled independently — no pattern detection
- Effort: Tiny — ~20 lines in codex-exec-wrapper.sh

### B. Repair Quality (Make Each Attempt Count)

**5. Failed approaches log (scratchpad)**
- Source: Praetorian
- Pattern: Repair contracts carry a `## Failed Approaches` section listing what was tried and why it failed. Repairing agent reads this first.
- Cortex gap: Repair contracts don't carry failure history — can repeat the same failed approach
- Effort: Small — new section in contract template

**6. Reflexion mandate (why-it-failed)**
- Source: Stevens Orchestrator-Reflexion, self-healing systems
- Pattern: Before proposing a fix, the repairing agent must articulate WHY the previous approach was wrong. This self-critique becomes input for the fix.
- Cortex gap: Repair recommendations describe what failed but not why
- Effort: Small — new required section in repair contract template

**7. Validator taxonomy (deterministic vs judgment)**
- Source: Braintrust, Nx Self-Healing CI
- Pattern: Classify validators as `[external]` (shellcheck, tests — always auto-apply fixes) vs `[judgment]` (LLM-scored — require review). Deterministic failures get auto-repair; judgment failures escalate.
- Cortex gap: All validators treated equally
- Effort: Small — annotation in contract validator section

**8. Completion promises**
- Source: Ralph Loop
- Pattern: Executor must emit explicit `CORTEX_PROMISE: contract-{ID} COMPLETE` signal. Hook checks for it. Without it, contract stays in execute state — prevents silent incomplete execution.
- Cortex gap: No explicit done signal from executor
- Effort: Small — check in cortex-task-completed hook

### C. Intelligence Depth (Better Evals + Memory)

**9. Scale-adaptive complexity tiers**
- Source: BMAD Method (Quick/Method/Enterprise tracks)
- Pattern: Clarify brief gets a `complexity` field (trivial/standard/complex) that gates downstream depth. Trivial: skip research, thin spec. Complex: multi-source research, ADRs, extended validators, security audit.
- Cortex gap: Every idea goes through the same pipeline regardless of complexity
- Effort: Medium — modify clarify brief, add conditional logic to research/spec skills

**10. Claim-level faithfulness scoring**
- Source: RAGAS, DeepEval
- Pattern: Extract individual claims from artifacts, verify each against source context. Score = verified_claims / total_claims. Catches specs that make unsupported assertions.
- Cortex gap: Artifact verification is at deliverable level only, not claim level
- Effort: Medium — new eval dimension + LLM-based claim extraction

**11. Cross-artifact coherence check**
- Source: BMAD (implementation readiness gate)
- Pattern: Before execution, verify that the spec addresses all clarify-brief goals and integrates all research findings. Catches drift between pipeline stages.
- Cortex gap: Spec-readiness gate checks completeness of intelligence, not coherence across artifacts
- Effort: Small — new validator in contract schema

**12. Semantic memory retrieval**
- Source: Mem0, CrewAI, LangGraph Store
- Pattern: Instead of loading all handoff files into context, extract discrete facts from sessions and store in searchable format (embeddings). Retrieve only what's relevant to current task. 14x token savings vs full-context loading.
- Cortex gap: Biggest token efficiency gap — all handoff files loaded equally
- Effort: High — requires embedding infrastructure (SQLite + vector extension or external)

**13. Memory extraction at compaction**
- Source: ADK Memory Bank, CrewAI's remember_many()
- Pattern: When compacting, decompose the summary into atomic facts (decisions, preferences, patterns) stored in structured format. Not just a markdown summary.
- Cortex gap: postcompact hook writes last-compact-summary.md but doesn't decompose into retrievable facts
- Effort: Medium — enhance postcompact hook

**14. Composite quality score**
- Source: Swarm-IOSM
- Pattern: Multi-dimensional quality index (0.0-1.0 per dimension, weighted composite). Enables quality trending over time, threshold-based gating, and comparing contract quality across milestones.
- Cortex gap: Gates are binary (pass/fail) with no composite score
- Effort: Medium — new eval-status.md format

**15. LLM-judge with calibration loop**
- Source: LangSmith Align Evals
- Pattern: LLM scores outputs against rubrics. Human samples and corrects disagreements. Corrections become few-shot examples that improve the judge over time.
- Cortex gap: No automated judgment scoring — ux_taste_eval is human-only
- Effort: High — requires calibration dataset infrastructure

### D. Routing Sophistication (Smarter Task Classification)

**16. Layered routing: static filter + LLM tiebreaker**
- Source: AutoGen (candidate_func + selector_func), Google ADK (description-based routing)
- Pattern: Keep static decision tree as primary. For ambiguous cases, add optional LLM pass that reads task XML + file headers and makes confidence-scored classification.
- Cortex gap: Static router only — ambiguous tasks default to Claude (conservative but wasteful)
- Effort: Medium — optional LLM call in task-router.js

**17. Event log for task execution**
- Source: OpenHands (event-sourced state)
- Pattern: Log structured events (task_started, file_edited, test_run, completed/failed) to append-only JSONL. Enables: replay on failure, post-mortem analysis, ML training data for router improvement.
- Cortex gap: No structured execution event log
- Effort: Small — append JSONL in codex-exec-wrapper.sh

**18. Iteration budget per task (step count)**
- Source: OpenHands (LOCAL_ITERATION counter)
- Pattern: Beyond wall-clock timeout, cap the number of file edits / tool calls per task. "Codex made 15 edits on a 3-file task — something is wrong."
- Cortex gap: Only wall-clock timeout, no step-count budget
- Effort: Small — parse JSONL event count during Codex execution

### E. Additional Patterns (Lower Priority)

**19. Project context constitution**
- Source: BMAD (project-context.md)
- Pattern: Single file encoding tech stack, conventions, and rules that ALL agents reference. Auto-generated from spec artifacts.
- Cortex gap: No project-level context file (CORTEX.md describes the framework, not the target project)
- Effort: Small — generate from spec during /cortex-spec

**20. Omission-focused review lens**
- Source: BMAD adversarial review
- Pattern: Review explicitly asks "what should be present based on the contract that isn't?" — looking for omissions, not just errors in what exists.
- Cortex gap: Reviews check what's there, not what's missing
- Effort: Tiny — add section to cortex-review SKILL.md

## Patterns to Explicitly NOT Adopt

| Pattern | Source | Why Not |
|---------|--------|---------|
| Named agent personas | BMAD | Adds cognitive load + false confidence. Same LLM with different system prompt. Cortex's functional agents are honest. |
| Minimum-issue review quotas | BMAD | Proven failure (GitHub #1332). Generates false positives, causes review fatigue. |
| Party Mode (multi-persona chat) | BMAD | Same model arguing with itself in different hats. No information gain. |
| Full mesh/swarm coordination | AutoGen, Swarm | Adds unpredictability without improving build system outcomes. |
| Pure LLM routing (no static rules) | CrewAI | Documented failures: wrong routing, delegation loops, sequential despite hierarchical config. |
| Graph memory for entities | Mem0g | Premature unless Cortex tracks many interconnected slugs. |
| Sleep-time background refinement | MemGPT/Letta | Adds complexity, requires background daemon. Low ROI for CLI tool. |
