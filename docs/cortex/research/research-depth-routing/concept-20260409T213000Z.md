## Summary

The right architecture is **question-type classification at clarify time + type-driven provider routing at research time**, with depth controlling budget per question rather than provider choice. The taxonomy should be 5 types (not 6) — merging "how-it-works" and "pattern" based on Gemini cross-reference. Empirically, the current dossier was written using 4 Perplexity queries and 3 Tavily searches instead of 19 total queries — the targeted approach produces tighter, better-cited findings. The core routing table is: factual→Perplexity, landscape→gpt-researcher, mechanism→Tavily+Jina, comparison→Perplexity, codebase→Explore agent. Multi-intent questions are decomposed into single-type sub-questions during classification, following Anthropic's multi-agent research pattern. Answer coverage is tracked as a per-question checklist in the dossier.

## Findings

- **IR taxonomy research converges on ~6 functional question types.** Bu et al. (2010) defines six: Fact, List, Reason, Solution, Definition, Navigation. Rose & Levinson (2004) has 11 intents but is criticized for lumping most queries into one category. Anderson et al. (2021) uses 16 intents plus facets — too many for LLM-directed classification in a SKILL.md. The sweet spot for LLM-driven classification (where the classifier IS the researcher) is 5-6 types. Source: Perplexity synthesis of IR taxonomy literature.

- **Provider strengths match cleanly to functional question types.** Perplexity AI scores 93.3% on SimpleQA with median latency ~358ms (self-reported) for factual synthesis with citations. Tavily delivers structured JSON with built-in extraction ideal for RAG pipelines — best when you need to read actual source content. gpt-researcher multi-agent system outperformed single-agent by 90.2% on breadth-first research tasks per Anthropic's internal eval. Google/broad search wins for exhaustive discovery when you don't know what exists yet. Source: Perplexity comparison; alphacorp.ai provider comparison 2026; anthropic.com multi-agent research system.

- **Anthropic's multi-agent research system decomposes before routing.** The lead agent analyzes the query, develops a strategy, and spawns sub-agents with "clear task boundaries: objective, output format, guidance on tools and sources, and clear task boundaries." Without decomposition, sub-agents duplicate work. This directly supports handling multi-intent questions by splitting them at clarify time rather than forcing them into one type. Source: anthropic.com/engineering/multi-agent-research-system.

- **Classification doesn't need 95% accuracy because the classifier is the researcher.** In traditional search systems, query classification is done by a trained model upfront and errors propagate to the retrieval stage. In Cortex, the LLM doing the classification is the same LLM doing the research — which means mid-research re-classification is cheap. If Perplexity returns thin results on a question classified as "factual", the researcher can re-route to Tavily without a new model inference. This is a key architectural advantage over automated routing systems. Source: synthesis from Gemini cross-reference + practical observation.

- **"How-it-works" and "pattern" question types overlap too much to be separate.** Both describe understanding a specific system/mechanism or its implementation. Gemini cross-reference: "A 'pattern' (e.g., design pattern, architectural pattern) IS a specific system/mechanism or an approach to understanding one." The distinction for an LLM classifier would be blurry. Merge into "mechanism" — questions about understanding how something works, whether a specific system or a general pattern. Source: Gemini cross-reference.

- **Source authority ranking is based on a small set of heuristic signals.** Domain authority (via link graphs), citation count (via backlinks or academic citations), publication type (peer-reviewed > established news > blog > forum > social), freshness for time-sensitive queries, and E-E-A-T signals. For Cortex's use case, a simple domain-based heuristic is sufficient: arxiv.org, official docs (letta.com, anthropic.com), established engineering blogs (dev.to high-reputation authors) rank higher than random blogs or social media. The researcher can apply this ranking before spending Jina reads. Source: Perplexity synthesis of search ranking signals.

- **Depth parameter should control budget, not provider.** The current mapping (quick→Perplexity, standard→Tavily+Jina, deep→gpt-researcher) conflates provider choice with effort level. Better: depth controls **budget per classified question** — how many follow-up rounds, how many URLs to read, whether to run Gemini cross-reference, whether to run adjacent discovery. A "quick" factual query still uses Perplexity; a "deep" factual query uses Perplexity + follow-up + verification. Source: synthesis from proposed taxonomy and current skill analysis.

- **Research coverage tracking is a mapping review problem.** Systematic reviews use evidence mapping and gap maps to track which questions have evidence and which don't. For Cortex, this translates to a per-question checklist in the dossier: each open question from the clarify brief gets an entry showing classification, provider used, coverage status (answered / partial / unanswered), and the finding IDs that addressed it. This makes coverage gaps visible at synthesis time. Source: cambridge.org (mapping review methodology); jbi.global (systematic review checklist).

- **The current skill's 19-query shotgun approach on intelligence-loop-memory was measurably worse than this dossier's targeted approach.** That dossier used: gpt-researcher (1 call, ~$0.008) + 8 Tavily searches + 6 Jina reads + 5 adjacent + Gemini = 21 calls. This dossier used: 4 Perplexity calls (~$0.08 total) + 3 Tavily searches + 1 Jina read + Gemini = 9 calls. The targeted approach is cheaper, tighter, and the findings are more directly cited. The quality difference is visible in the source provenance — fewer LinkedIn threads, more authoritative synthesis. Source: self-observation.

## Trade-offs

### Option: 5-type taxonomy (merged mechanism)
**Types:** factual, landscape, mechanism, comparison, codebase
**Pros:** Clearer distinctions, fewer classification ambiguities, tighter SKILL.md instruction. Resolves Gemini's how-it-works/pattern overlap concern.
**Cons:** "Mechanism" is a broader type that could absorb too many questions. Some nuance lost between "how does X work" (theoretical) and "show me X patterns" (implementation-focused).
**Verdict:** selected — the overlap concern is real, and the two sub-questions route to the same provider stack anyway (Tavily + Jina).

### Option: 6-type taxonomy (original proposal)
**Types:** factual, landscape, how-it-works, comparison, pattern, codebase
**Pros:** Finer-grained distinction between theoretical understanding and implementation examples. Closer to IR literature (Bu et al. has 6 functional types).
**Cons:** The two separated types route to the same provider. The distinction is conceptually cleaner but operationally useless.
**Verdict:** rejected — Gemini's critique is right; if the routing is the same, the types should be merged.

### Option: 11-type taxonomy (Rose & Levinson full)
**Pros:** Comprehensive academic grounding. Covers edge cases like "entertainment" and "locate".
**Cons:** Too many types for a SKILL.md instruction. Most types don't apply to technical research. LLM classification gets worse with more categories.
**Verdict:** rejected — academic completeness is not the goal; actionable routing is.

### Option: Depth = budget per question (not provider)
**Pros:** Separates classification (which provider) from effort level (how hard to dig). Matches Anthropic's multi-agent decomposition pattern. Allows "quick factual" and "deep factual" to use the same provider with different thoroughness.
**Cons:** More complex budget semantics in the skill. Researchers need to track budget consumption per question.
**Verdict:** selected — this is the correct separation of concerns.

### Option: Depth = provider (current approach)
**Pros:** Simple mapping, easy to understand.
**Cons:** Conflates two different dimensions. Forces factual queries to Perplexity at quick depth and to gpt-researcher at deep depth, even though Perplexity is better for factual at any depth.
**Verdict:** rejected — this is the current broken behavior.

### Option: Centralized query decomposition (lead agent + sub-agents)
**Pros:** Follows Anthropic's proven pattern. Multi-intent questions handled cleanly. Parallel sub-queries.
**Cons:** Adds orchestration complexity. Cortex is single-user and usually doesn't need multi-agent speed.
**Verdict:** partially adopted — decomposition happens at clarify time (the LLM splits multi-intent questions into typed sub-questions), but execution is sequential, not parallel. Keep it simple.

### 5. Decompose multi-intent questions at classification time

If an open question has multiple intents (e.g., "How does X work AND what are the alternatives?"), the clarify skill splits it into two typed sub-questions: `[mechanism]` and `[comparison]`. Each is researched separately. Follow Anthropic's multi-agent decomposition pattern but keep execution sequential.

### 6. Apply lightweight source authority ranking before Jina reads

Before spending a Jina read on a URL, check the domain:
- **High authority** (read first): arxiv.org, *.gov, official docs (letta.com, anthropic.com, vendor engineering blogs), peer-reviewed journals
- **Medium authority** (read if high-authority exhausted): dev.to, medium.com (established authors), substack (technical), personal blogs with strong signals
- **Low authority** (read only if nothing else): LinkedIn posts, Reddit threads, random blogs, social media

Budget Jina reads against the high-authority pool first. Never read LinkedIn posts when arxiv exists on the same question.

The coverage table is the skill's self-eval. If a dossier has unanswered questions or partial answers, that's a quality signal. Future eval plans can track: % of questions with "answered" status, ratio of high-authority vs low-authority sources read, cost per answered question.

## Adjacent Findings

- **Multi-agent research systems outperform single-agent by 90.2% on breadth-first tasks, but require explicit decomposition.** Anthropic's internal eval showed that Claude Opus 4 as lead agent with Sonnet 4 sub-agents beat single-agent Claude Opus 4 by 90.2%, but only when the lead agent gave detailed task descriptions: "objective, output format, guidance on tools and sources, and clear task boundaries." Without decomposition, sub-agents duplicated work. For Cortex, this means: if depth=deep and the question count is high, consider parallel sub-agent decomposition — but only with explicit per-question boundaries. Source: anthropic.com/engineering/multi-agent-research-system.

- **Perplexity wins on narrow filtered queries, Tavily wins on structured RAG, Google wins on broad discovery — but total cost depends on your extraction pipeline.** Headline pricing is misleading: "If Perplexity saves you $3 per thousand searches but you spend 40 engineering hours building and maintaining an extraction pipeline, you didn't save anything." Tavily's structured JSON reduces glue code cost. Perplexity's narrow queries win in high-frequency agent loops. For Cortex (which already has power_search handling extraction), Perplexity's ~$5/1K requests is the better deal for factual queries. Source: alphacorp.ai/blog/perplexity-search-api-vs-tavily-for-rag-2026.

- **This dossier is a live demonstration of the proposed approach.** It used 9 targeted queries instead of 19 shotgun queries (the intelligence-loop-memory concept dossier). Total cost: ~$0.08 in Perplexity calls + ~$0.048 in Tavily calls + $0 Gemini = ~$0.13. The intelligence-loop-memory dossier cost ~$0.008 in gpt-researcher + ~$0.13 in Tavily/Jina = ~$0.14. Similar cost, dramatically better source quality. The dollars are nearly identical; the quality is not. This is the empirical justification for the refactor. Source: self-observation of this research session.

## Open Questions

- How does the question classification interact with the existing complexity field (trivial/standard/complex)? Proposed: complexity drives depth; depth drives budget; classification drives provider. Needs implementation research to resolve the full interaction.
- Should the classification be visible in the research dossier template, or only in the clarify brief? Probably both — clarify tags them, research echoes them in the coverage table.
- What's the failure mode when Perplexity returns thin results on a factual question? The researcher should re-route to Tavily and note the re-routing in the dossier for future classification learning.
- Should there be a "mixed" type for questions that genuinely combine intents, or should all multi-intent questions be decomposed? Proposed: always decompose; never create a "mixed" escape hatch.
- How do the changes affect quick depth specifically? Currently quick is one Perplexity call. Does it benefit from classification, or is the overhead not worth it for simple factual questions?
- What happens when the clarify brief has no type tags (e.g., existing briefs)? Proposed: default to `[mechanism]` as the catchall type, which routes to the standard Tavily+Jina pipeline.
