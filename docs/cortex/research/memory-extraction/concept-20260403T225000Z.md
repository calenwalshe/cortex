# Research Dossier: memory-extraction — concept

**Slug:** memory-extraction
**Phase:** concept
**Timestamp:** 20260403T225000Z
**Depth:** standard (codebase analysis + pattern research)

---

## Summary

The postcompact hook currently writes a flat markdown summary with metadata (slug, mode, contract path) but drops all session intelligence — decisions made, approaches tried, patterns discovered, constraints identified. The hook receives no stdin data (it's a simple command hook) and can only read from disk. The precompact hook saves current-state.md + state.json as a snapshot, which is also just metadata.

The extraction approach must work without LLM calls (hooks can't call APIs) and without session transcript access (PostCompact hooks don't receive transcript data). The viable approach: enhance the precompact hook to capture richer data from existing Cortex artifacts, and enhance the postcompact hook to decompose that data into atomic facts.

## Findings

### 1. Current Hook Architecture

**cortex-precompact.sh** (PreCompact event):
- Reads: `docs/cortex/handoffs/current-state.md`, `.cortex/state.json`
- Writes: `.cortex/compaction/precompact-{timestamp}.md`
- Content: metadata snapshot only (slug, mode, contract path, state.json dump)
- Does NOT read: conversation context, decisions.md, CONTEXT.md files, recent git commits

**cortex-postcompact.sh** (PostCompact event):
- Reads: `.cortex/state.json`, latest precompact snapshot
- Writes: `docs/cortex/handoffs/last-compact-summary.md`, `docs/cortex/handoffs/next-prompt.md`
- Receives: no stdin data (simple command hook, not PostToolUse-style)
- Content: minimal recovery instructions

### 2. Available Intelligence Sources (readable from hooks)

These files contain extractable session intelligence:

| Source | Contains | Location |
|--------|----------|----------|
| `docs/cortex/handoffs/decisions.md` | Decision log, autonomy decisions | Always exists |
| `docs/cortex/handoffs/current-state.md` | Slug, mode, artifacts, blockers | Always exists |
| `.planning/STATE.md` | GSD progress, accumulated context, decisions, blockers | When GSD active |
| `.planning/phases/*/CONTEXT.md` | Implementation decisions, deferred ideas | Per phase |
| `git log --oneline -20` | Recent work context | Always exists |
| `.cortex/state.json` | Pipeline state, gates, approvals | Always exists |

### 3. Fact Categories (from ADK Memory Bank + CrewAI analysis)

ADK Memory Bank uses 4 categories: Core (identity/purpose), Progress (completed/remaining), Decisions (choices/rationale), Patterns (learned approaches). CrewAI's remember_many() extracts: short-term (current task), long-term (cross-session), entity (relationship graph).

For Cortex, the right categories are:

1. **decision** — A choice made with rationale (from decisions.md, CONTEXT.md decisions sections)
2. **preference** — User behavioral pattern (from CONTEXT.md specifics, repeated choices)
3. **constraint** — Hard limit discovered during work (from clarify brief, spec constraints)
4. **pattern** — Implementation approach that worked or failed (from STATE.md accumulated context)
5. **blocker** — Active blocker or resolved blocker with resolution (from STATE.md blockers)
6. **context_pointer** — Reference to where to find information (file paths, artifact locations)

### 4. Storage Format

JSONL is the right choice:
- Append-friendly (one fact per line, no need to parse full file)
- Future-embedding-compatible (each line is an independent document)
- Efficient to read (stream line-by-line, no full load)
- Grep-friendly for ad-hoc lookup

Schema per fact:
```json
{
  "id": "fact-{timestamp}-{seq}",
  "type": "decision|preference|constraint|pattern|blocker|context_pointer",
  "slug": "memory-extraction",
  "text": "Chose JSONL over SQLite for fact storage because hooks can't use npm packages reliably",
  "source": "docs/cortex/handoffs/decisions.md",
  "extracted_at": "20260403T225000Z",
  "session_context": "memory-extraction clarify phase"
}
```

### 5. Extraction Approach

Since hooks can't call LLMs, extraction must be pattern-based:

1. **decisions.md** — Parse `## Decision Log` entries. Each `- ` line is a fact of type `decision`.
2. **STATE.md** — Parse `### Decisions` section. Each line is a fact.
3. **STATE.md** — Parse `### Blockers/Concerns` section. Each line is a `blocker` fact.
4. **CONTEXT.md** — Parse `<decisions>` sections for `decision` facts, `<specifics>` for `preference` facts.
5. **git log** — Last 20 commits summarize recent work. Each commit message is a `context_pointer` fact.
6. **current-state.md** — Artifact paths become `context_pointer` facts.

### 6. Deduplication

Use content hash (first 8 chars of MD5 of `text` field) as part of the fact ID. Before appending, grep the existing facts file for the same hash. Skip if duplicate.

### 7. Performance Budget

The hook must complete in <5 seconds. Budget:
- Read 5-7 files: ~50ms
- Pattern extraction: ~100ms (node regex on small files)
- Dedup check (grep existing JSONL): ~50ms
- Write new facts: ~10ms
- Total: ~210ms — well within budget

## Recommendations

1. **Enhance precompact hook** to capture richer data: read decisions.md, STATE.md accumulated context, recent CONTEXT.md files, and git log. Write all to the precompact snapshot.
2. **Rewrite postcompact hook** as Node.js (not bash) for reliable JSON manipulation. Read the enriched precompact snapshot + existing Cortex artifacts. Extract atomic facts. Append to `.cortex/facts.jsonl`.
3. **Store facts in `.cortex/facts.jsonl`** — one file, append-only, deduped by content hash.
4. **6 fact categories**: decision, preference, constraint, pattern, blocker, context_pointer.
5. **No TTL needed** for v1 — facts accumulate. Pruning can be added later if file grows beyond ~1MB.

## Open Questions Resolved

- **Fact categories**: 6 categories (decision, preference, constraint, pattern, blocker, context_pointer)
- **Precompact content**: Metadata-only today. Enhancement needed to capture richer data.
- **TTL**: Not needed for v1. Append-only with dedup.
- **Duplicate handling**: Content hash dedup before append.
- **Max size**: Not a concern for v1 — typical project produces <100 facts per milestone.
