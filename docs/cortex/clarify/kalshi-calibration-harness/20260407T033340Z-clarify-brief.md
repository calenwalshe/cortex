## Idea

Fork Cortex to create a prediction market intelligence agent that uses Kalshi betting outcomes as a calibration mechanism. Real money P&L becomes ground truth for evaluating and improving Cortex's reasoning pipeline. The system uses the clarify-research-spec-review cycle to analyze prediction markets, form positions with calibrated confidence levels, place bets, and then run structured post-mortems on outcomes to identify which phases of the reasoning pipeline fail and how to fix them. This is not a trading bot — it's an evaluation harness for intelligence work that happens to use prediction markets as the scoring function.

---

## Goal

Build a Cortex fork (cortex-kalshi) that uses Kalshi prediction market outcomes as unambiguous, P&L-denominated feedback signals to systematically identify and fix weaknesses in the reasoning pipeline — producing measurable calibration improvement over time.

---

## Non-Goals

- Not building a high-frequency or algorithmic trading system
- Not optimizing for maximum profit — the P&L is a signal, not the objective
- Not replacing Cortex's general-purpose pipeline — this is a parallel fork for domain-specific calibration work
- Not building a Kalshi API wrapper library — use existing SDKs
- Not attempting to automate bet execution initially — manual placement is fine while the reasoning pipeline is being calibrated
- Not market-making or providing liquidity

## Assumptions

- Kalshi's API provides sufficient market data and programmatic access for position tracking and outcome verification
- The Cortex reasoning pipeline (clarify-research-critic) produces outputs that can be meaningfully converted to probability estimates
- Prediction market outcomes are a valid proxy for reasoning quality (i.e., calibration errors correlate with pipeline failures, not just irreducible uncertainty)
- Small-stakes betting ($5-50 per position) provides sufficient signal without unacceptable financial risk
- Binary event markets with defined resolution dates exist in sufficient volume on Kalshi to provide regular feedback cycles
- Git fork with upstream/downstream remotes is sufficient for bidirectional code flow between cortex and cortex-kalshi

- What Kalshi API capabilities are available — can we programmatically fetch market data, track positions, and verify outcomes?
- How do we measure calibration improvement over time — Brier score, log loss, calibration curve binning, or something simpler?
- What is the right cadence — how many bets per week to generate statistically meaningful signal?
- Should the fork diverge at the skill level (new/modified SKILL.md files) or at the infrastructure level (new pipeline stages)?
