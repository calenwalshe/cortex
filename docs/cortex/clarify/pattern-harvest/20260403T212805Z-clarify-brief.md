# Clarify Brief: pattern-harvest

**Slug:** pattern-harvest
**Timestamp:** 20260403T212805Z
**Status:** draft

---

## Idea

Comprehensive analysis of competing AI agent orchestration systems (BMAD Method, LangGraph, CrewAI, Pydantic AI, Google ADK, Roo Code, Praetorian Deterministic Orchestration, Senior AI Orchestrator, Swarm-IOSM) to identify patterns that fit Cortex's artifact-driven, contract-gated philosophy. Extract concrete, implementable patterns — not vague inspiration — that would make Cortex better without changing its core identity.

---

## Goal

A prioritized catalog of patterns from competing systems that are compatible with Cortex's artifact-driven architecture, with concrete implementation sketches for each — ready to feed into spec work for the next milestone.

---

## Non-Goals

- Not adopting role-based agent personas (Cortex is artifact-driven, not persona-driven)
- Not switching to a different orchestration framework (LangGraph, CrewAI, etc.) — Cortex stays as a SKILL.md instruction layer
- Not building a general-purpose agent framework — Cortex is opinionated about its pipeline
- Not copying UI/UX patterns from VS Code extensions (Roo Code) — Cortex is CLI-native

---

## Constraints

- Patterns must work within Cortex's SKILL.md instruction architecture — no new runtime dependencies
- Patterns must preserve the artifact pipeline (clarify → research → spec → contract → execute)
- Patterns must be compatible with the GSD execution layer (Cortex doesn't own execution)
- Must fit the existing autonomy config system (gates, presets, mandatory gates)

---

## Assumptions

- The systems identified in our prior research (BMAD, LangGraph, CrewAI, Pydantic AI, Google ADK, Roo Code, Praetorian, Senior AI Orchestrator) represent the current state of the art
- Cortex's core strength is its artifact-driven pipeline with contract enforcement — patterns should enhance this, not replace it
- Some patterns may already be partially implemented in Cortex without us realizing it

---

## Open Questions

- What does BMAD's ideation→spec transition look like concretely? How does it compare to Cortex's clarify→research→spec pipeline?
- What quality gate patterns from Praetorian's deterministic orchestration are missing from Cortex?
- How does CrewAI's hierarchical delegation compare to Cortex's subagent spawning? Are there improvements?
- What does Google ADK's "LLM-driven dynamic routing" look like? Is it better than Cortex's static task router?
- What self-healing/self-annealing patterns exist that Cortex's repair loop doesn't cover?
- What evaluation patterns (LangSmith, Braintrust, RAGAS) could improve Cortex's eval subsystem?
- Are there memory/state persistence patterns Cortex is missing?

---

## Next Research Steps

1. Deep-dive BMAD Method — read their full docs, understand the pipeline, extract transferable patterns
2. Deep-dive Praetorian Deterministic Orchestration — read the paper/framework, extract quality gate and state machine patterns
3. Analyze LangGraph's state persistence and checkpoint patterns — compare to Cortex's continuity system
4. Analyze CrewAI's delegation and tool permission model — compare to Cortex's write root enforcement
5. Research eval/observability patterns from LangSmith, Braintrust, RAGAS — compare to Cortex's eval subsystem
6. Research self-healing agent patterns (Senior AI Orchestrator, Swarm-IOSM) — compare to Cortex's repair loop
7. Synthesize: for each pattern found, assess compatibility with Cortex's architecture and estimate implementation effort
