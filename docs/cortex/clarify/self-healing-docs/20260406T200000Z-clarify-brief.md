## Idea

Build a machine-readable command registry and a merge-blocking doc drift check so that documentation inconsistencies like the one we just fixed (COMMANDS.md showing 8 commands when 13 existed) can never happen again. F1 from autonomous-builder-ideas.md: one spec per command (syntax, inputs, outputs, state effects) that generates reference docs. F4: a check-doc-drift script that blocks if documented ≠ installed (covers skills, hooks, manifest, installer flags).

---

## Goal

Every Cortex command, hook, and agent is documented from a single source of truth — adding a new skill automatically keeps all reference docs correct, and any drift between installed components and documentation is caught before merge.

---

## Non-Goals

- [owner-intent] No code without contract. Production code must not be written before a contract is approved.
- [owner-intent] Disk is truth. All state lives in repo artifacts.
- Not redesigning the SKILL.md format — skills remain the behavioral source of truth. The registry extracts metadata from them.
- Not building a docs website or static site generator — output is markdown files in the repo
- Not automating SKILL.md creation — that stays human-authored
- Not changing how commands work at runtime — this is documentation infrastructure only
- Not implementing F2 (bridge registry), F3 (full generated reference docs), F5 (reference integrity eval dimension), or F6 (thin README) from the builder ideas — those are follow-ons

---

## Constraints

- [owner-intent] Validators must run. No slug closes without validators passing.
- [owner-intent] GSD owns execution. Cortex does not write to .planning/ except via /cortex-bridge.
- Registry must be derivable from existing SKILL.md files — no second source of truth that can go stale
- The drift check must run as a git hook or CI check — not just a manual command
- Must handle the current 14 commands, ~20 hooks, and 4 agents
- Output must be deterministic — same input always produces same output (no LLM in the generation path)

---

## Assumptions

- SKILL.md files are the canonical behavioral spec for each command — they contain syntax, inputs, outputs, rules
- runtime-manifest.json is the canonical list of what's installed
- The drift check compares manifest against docs, not against actual installed files (repo-level, not machine-level)
- COMMANDS.md is the generated target — it becomes output, not hand-edited
- A simple extraction script (node or bash) can parse SKILL.md headers/sections for registry metadata
- The hook docs (HOOKS.md) and agent docs (AGENTS.md) should also be generated from registry, not just commands
