## Idea

Wire in a lifecycle close mechanism for Cortex: once a slug's work is done, archive its artifacts to a cold path, define `done` as an explicit state in state.json, and clear the active surface so `/cortex-status` comes up clean for the next slug. The system currently accumulates artifacts indefinitely with no terminal state.

---

## Goal

Add a `done` mode to state.json and a `/cortex-close` command (or `--archive` flag on `/cortex-status`) that copies completed slug artifacts to `docs/cortex/archive/{slug}/`, clears `current-state.md`, and writes a timestamped index entry to `docs/cortex/handoffs/decisions.md` — giving every slug a complete, auditable lifecycle from clarify to archive.

---

## Non-Goals

- Moving artifacts — archive is copy-only; source paths stay intact for reference
- Automatic archive on contract close — archive is always an explicit human action
- Modifying GSD `.planning/` state — this is a Cortex-layer operation only
- Deleting or rotating source artifacts after archiving — they persist in their original locations
- Archiving partial slugs — archive is only valid when all done_criteria are met or mode is `done`
- Replacing the existing `/clear` + `/cortex-status` recovery system — that is untouched

---

## Constraints

- Archive must copy, not move — `docs/cortex/clarify/{slug}/`, `docs/cortex/specs/{slug}/`, etc. remain in place after archive
- `done` must be an explicit mode in state.json — the archive trigger checks `mode == "done"`, not a heuristic
- Archive must not modify `.planning/STATE.md` or any GSD phase state
- `current-state.md` must be cleared (reset to "not started" state) after archive completes — `/cortex-status` must return clean
- The archive index entry in `decisions.md` must be timestamped and include: slug, close date, active contract path, eval plan path

---

## Assumptions

- The minimum artifact set to archive is: clarify brief, research dossier(s), spec.md, gsd-handoff.md, contract, eval-proposal, eval-plan — i.e., everything in `artifacts[]` from state.json at close time
- `mode == "done"` is the correct trigger — not "all done_criteria checked" in the contract (which requires reading the contract file)
- A new `/cortex-close` command is preferable to an `--archive` flag on `/cortex-status` — close is a distinct, consequential action that warrants its own entry point
- The archive index in `decisions.md` is append-only — existing entries are never modified
- The phase guard (`cortex-phase-guard.sh`) does not need to be updated — archive writes only to `docs/cortex/` and `.cortex/`, which are already permitted paths

## Open Questions

- Should `/cortex-close` require explicit confirmation before writing (e.g., "type the slug to confirm") given it modifies current-state.md?
- What happens if archive is run on a slug that has no eval-plan — is that a blocker or a warning?
- Should `docs/cortex/archive/` be a flat directory or mirror the subdirectory structure (`archive/{slug}/clarify/`, `archive/{slug}/specs/`, etc.)?
- Should the archive index in `decisions.md` replace that file's current structure or be a new appended section?
- Is there a `/cortex-unarchive` or is archive always one-way?
