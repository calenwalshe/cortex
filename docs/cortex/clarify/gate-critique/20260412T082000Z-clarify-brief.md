# Clarify Brief: gate-critique

## Idea

Add an explicit critique phase at each gate — AI critique and human critique run in parallel before any gate advances.

---

## Goal

Every Cortex gate has a structured dual-critique step — adversarial AI review plus owner plain-language feedback — that must complete before the gate advances, so bad assumptions and poor framing are caught before they propagate downstream into expensive work.

---

## Non-Goals

- Not replacing the existing gate approval checkpoints (contract_approval, reclarify, etc.) — critique feeds the approval decision, it does not replace it
- Not critiquing code or implementation output — that is the domain of `/cortex-review` and `/cortex-audit`
- Not a full security red-team or STRIDE threat model pass
- Not auto-blocking gate advancement based solely on AI critique findings — AI critique informs the human decision, it does not veto
- Not retroactive critique of artifacts already approved in prior slugs

---

## Constraints

- [owner-intent] Disk is truth — if critique findings exist, they must be persisted as artifacts, not only shown inline in chat
- [owner-intent] No code without contract — critique cannot delay contract approval to the point where execution begins without an approved contract
- AI critique must be adversarial and devil's advocate — a critique that only confirms what the artifact says is worthless and wastes a gate slot
- AI critique is implemented via Codex CLI invoked with `exec` mode (`codex exec --full-auto ...`) and an explicit adversarial framing in the prompt — the prompt must tell Codex upfront that its role is adversarial critic, not assistant. This is a confirmed implementation decision, not a suggestion.
- Human critique must be lightweight — the owner cannot be asked to read 3–5 files before weighing in; the critique interface must surface the AI's findings in plain language first
- AI critique always runs — it is not gated by autonomy preset. Human critique is the gate that full-auto can skip. This is a confirmed design decision, not an assumption.
- Critique must complete in a single pass — it cannot spawn research sub-loops or request additional context that would delay the gate indefinitely

---

## Assumptions

- Gates (clarify→research, research→spec, spec→contract) are the right insertion points — critique inserted at every phase transition would be excessive; critique mid-phase would have incomplete artifacts to evaluate
- Unstructured AI self-critique (i.e., "does this look right?") is insufficient — a structured adversarial prompt with specific critique dimensions is needed to produce findings that aren't just confirmatory
- The `cortex-critic` subagent type already exists and is relevant — the question is whether it satisfies AI critique at gates or whether a new skill is needed
- "Parallel" in a terminal session context means AI critique runs first, then the human sees both the artifact and the AI critique findings before responding — true simultaneity is not achievable, but presenting AI findings before asking for human input achieves the same outcome
- Critique findings from prior gates should be visible to later gates — a spec critique should know what the clarify brief critique flagged, to check whether concerns were addressed
