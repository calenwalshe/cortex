## Idea

Looking to take Firecrawl, Tavily, Jina, Perplexity, Crawl4AI, as well as other skills like CLI tools, and make them skills that are callable in a general Claude session independent of Cortex — so that they can be recognized and triggered independently.

---

## Goal

Build 4 grouped global Claude Code skills (`/web`, `/google`, `/ai`, `/cli`) that expose Firecrawl, Tavily, Jina, Perplexity, Crawl4AI, Gmail, Google Drive, Gemini, Imagen, Stitch, GPT, and shell execution as first-class capabilities in any Claude session — replacing WebSearch/WebFetch as the default, independent of Cortex.

---

## Non-Goals

- Not a replacement for `/cortex-research` — that skill continues to orchestrate these tools for structured dossier production
- Not changing the internal logic of existing tools — purely an exposure/packaging problem
- Not adding new tool integrations — only promoting what already exists
- Not building an MCP server — skills invoke APIs via Bash/Python, not the MCP protocol
- Not modifying the Cortex phase gate system or continuity state machine

---

## Constraints

- Skills must work without any `.cortex/state.json` present — no slug, no clarify brief dependency
- Must use the existing API keys already in environment (`FIRECRAWL_API_KEY`, `TAVILY_API_KEY`, `PPLX_API_KEY`, etc.)
- Output defaults to chat (not file artifacts) since there is no project context to route to
- Must follow the Claude Code skill format (SKILL.md-based, in `~/.claude/skills/`)
- Skills live directly in `~/.claude/skills/` as global skills — NOT in `~/projects/cortex/` — they are user-level, not project-level
- `cli-anything` plugin is installed and already handles generic CLI passthrough — new CLI skills should complement, not duplicate it
- These skills REPLACE Claude's built-in `WebSearch` and `WebFetch` as the default for any web operation. Built-in tools are only used when the user explicitly requests them (e.g., "use WebFetch", "use built-in search")

---

## Assumptions

- All required API keys are already in the environment (confirmed: FIRECRAWL, TAVILY, PPLX in env)
- The user wants natural-language triggers, not just slash commands (e.g., "scrape this URL" → Firecrawl fires automatically)
- Results go to chat by default; an optional `--save <path>` flag can write to disk
- `/cortex-research` should remain unchanged — it will internally call the same logic these standalone skills expose
- Skills should be minimal — thin wrappers over the API calls, not full pipeline orchestration
- The "CLI skills" the user references likely means Firecrawl's CLI mode and/or other tool CLIs, not a generic terminal wrapper
- Naming uses semantic verbs (`/scrape`, `/search`, `/fetch`) not tool names — implementation detail is hidden from the user
