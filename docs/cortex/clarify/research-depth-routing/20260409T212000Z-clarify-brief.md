# Clarify Brief: research-depth-routing

**Slug:** research-depth-routing
**Timestamp:** 20260409T212000Z
**Status:** draft
**Complexity:** standard

---

## Idea

Refactor cortex-research depth routing: deep should use Perplexity first for targeted factual questions per open question, gpt-researcher for broad landscape survey, Tavily only for gap-filling. Add quality ranking step before URL reads (authority scoring). Track answer coverage per open question from clarify brief. Read fewer URLs more deeply instead of shotgunning. The current skill maps deep exclusively to gpt-researcher which produces high-volume uneven-quality output.

**Reframed (user clarification):** The routing should be task-type-driven, not depth-driven. The clarify step should classify each open question and research step by type (e.g., factual lookup, landscape survey, implementation pattern, comparison). The research router then picks the right provider and strategy per question type. This means modifying both cortex-clarify (to output question classifications) and cortex-research (to consume them).

---

## Goal

The clarify-to-research handoff includes a question-type classification for each open question and research step, and the `/cortex-research` skill routes each classified question to the optimal provider and strategy — so that research quality comes from matching the right tool to the right question type, not from increasing search volume.

---

## Non-Goals

- Not a rewrite of the entire cortex-research skill — focused on the routing logic, source selection, and coverage tracking
- Not adding new search providers — working with existing power_search providers (Perplexity, Tavily, Jina, Gemini, gpt-researcher)
- Not changing the dossier output format or template
- Not modifying the adjacent discovery pipeline (Outside-In, I&W, filter pipeline) — those are separate from primary research routing
- Not building a search quality evaluation framework — the quality ranking is a lightweight heuristic, not a scored system
- Not a full rewrite of cortex-clarify — only adding question-type classification to the existing Open Questions and Next Research Steps sections

## Assumptions

- Perplexity sonar produces tighter, better-cited synthesis than gpt-researcher for targeted factual questions
- gpt-researcher is still valuable for broad landscape surveys where you need to discover what exists, not answer a specific question
- Source authority is roughly estimable from URL domain (e.g., arxiv.org > reddit.com > random blog) without needing a full scoring system
- Tracking answer coverage per open question will naturally reduce shotgun searching because the researcher knows when to stop
- Reading 3 high-quality sources deeply produces better findings than reading 6 sources at 8K chars each

- What's the routing table mapping question types to providers? (e.g., factual-lookup → Perplexity, landscape-survey → gpt-researcher, implementation-pattern → Tavily + deep URL reads)
- How should source authority ranking work? Simple domain-based heuristic, or something more nuanced?
- How should answer coverage be tracked and displayed? A checklist per open question? A coverage score in the dossier?
- Should the depth levels (quick/standard/deep) be redefined in terms of question-type routing budgets rather than fixed provider assignments?
- How does this interact with the existing complexity field (trivial/standard/complex)? Complexity drives depth, but question types drive routing within that depth.
