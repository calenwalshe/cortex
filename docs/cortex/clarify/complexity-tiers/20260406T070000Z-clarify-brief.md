## Idea

Add conditional logic to the Cortex pipeline so that the complexity field in the clarify brief (trivial/standard/complex) gates downstream behavior. Trivial slugs skip research and get thin specs. Complex slugs get extended validators, deeper research, and security audit. Standard stays as-is. The clarify brief template already has the complexity field — the downstream commands (cortex-research, cortex-spec, cortex-bridge, cortex-review) don't read it yet.

---

## Goal

The Cortex pipeline adapts its depth to the work — trivial ideas cost fewer tokens and reach execution faster, complex ideas get deeper scrutiny — so autonomous runs are both cheaper and safer.

---

## Non-Goals

- Not changing the clarify brief template (complexity field already exists)
- Not adding auto-detection of complexity (human or cortex-drive sets it at clarify time)
- Not adding new commands or lifecycle modes
- Not changing the sequential spine order (clarify → research → spec → execute)
- Not implementing the full BMAD Quick/Method/Enterprise split — just conditional depth within existing commands

---

## Constraints

- All changes must be in SKILL.md files (instruction architecture, no runtime dependencies)
- Backward compatible — slugs without a complexity field default to `standard`
- The complexity field is advisory at clarify time — research and spec skills can upgrade complexity if they detect the work is harder than labeled (already documented in the template comment)
- Must not break cortex-drive's decision table — drive needs to read complexity and adjust its dispatching

---

## Assumptions

- cortex-research SKILL.md is where research depth/skip logic lives
- cortex-spec SKILL.md is where spec thinning/extending logic lives
- cortex-review SKILL.md is where extended validator logic lives for complex slugs
- cortex-drive SKILL.md reads the clarify brief and can route based on complexity
- The existing `--depth` flag on cortex-research (quick/standard/deep) maps naturally to complexity tiers
- Security audit (/cortex-audit) is already a standalone command — complex tiers just mandate it

## Open Questions

- Does cortex-drive need to set complexity automatically based on heuristics, or always inherit from the clarify brief?
- Should complex slugs mandate eval plans before spec approval (stricter than standard)?
- What's the token savings estimate for trivial vs standard pipeline?
