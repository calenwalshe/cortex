## Summary

Prototyped and validated a necessity attack gate using Claude Haiku 4.5 against 4 ground-truth cases from this session's work. The gate correctly returned REJECT for verifier-harness (the slug we killed), BUILD for semantic-retrieval and execution-supervisor, and NARROW for a hypothetical bloated scope. 4/4 correct verdicts, 0.85-0.92 confidence range, $0.0016/check, ~3.8s latency. Implementation approach: inline LLM call in /cortex-spec Phase 1 (not a separate script or critic agent extension). The prompt template is proven and ready for integration.

## Prompt Design

The working prompt has 5 key elements:

1. **Four verdict options with definitions** — BUILD/NARROW/DEFER/REJECT, each with a clear trigger condition
2. **Adversarial framing** — "default should be skepticism, not approval"
3. **Five diagnostic questions** — who has this problem? existing system already handles it? human would notice? solution looking for a problem? simpler approach?
4. **Clarify brief + research findings + key context** — the gate reads what clarify and research already produced
5. **Structured JSON output** — verdict, confidence, reasoning, evidence array

The prompt works because it asks the right questions. The verifier-harness case failed on "who actually has this problem?" — the answer was "nobody, the AI handles it." That's exactly the question the gate is designed to surface.

## Design Decisions — All Resolved

### 1. Implementation → Inline LLM call in /cortex-spec Phase 1

**Decision:** Add the necessity check as a new gate step in /cortex-spec's Phase 1 (prerequisite validation), using a direct Claude API call via the same session's model.

**Evidence:**
- The check is a judgment call, not a mechanical check — needs LLM reasoning
- cortex-critic is read-only and doesn't return verdicts — wrong tool
- A separate script would add a subprocess + API call overhead unnecessarily
- /cortex-spec already makes LLM calls for coherence checks — this is the same pattern
- The check runs in the same context where the clarify brief and research dossier are already loaded

**Why not extend cortex-critic:**
- The critic reviews specs/contracts after they're written. The necessity gate runs before spec is written. Different lifecycle position.
- The critic doesn't return verdicts (its output says "APPROVED | NEEDS_REVISION"). The necessity gate needs BUILD/NARROW/DEFER/REJECT.
- Extending the critic would conflate two different jobs: "is this spec correct?" vs "should this spec exist?"

**Why not a separate script:**
- Would need its own API key handling, model config, and CLI — overhead for a single-purpose check
- The check needs the clarify brief and research dossier — /cortex-spec already reads those

### 2. Verdict Heuristics → Prompt-based, not rule-based

**Decision:** The verdict is LLM judgment against the five diagnostic questions, not a mechanical rule.

**Evidence:**
- The verifier-harness case couldn't be caught by any simple rule. The research was solid (parser works, validators found). The problem was "who has this problem?" — a judgment call.
- Rule-based approaches (e.g., "reject if <N users affected") can't capture "solution looking for a problem"
- The LLM correctly applied the diagnostic questions in all 4 test cases

**The five diagnostic questions (proven effective):**
1. Who actually has this problem? Human user or system solving its own problem?
2. Does the existing system handle this adequately, even if imperfectly?
3. Would a human notice if this didn't exist?
4. Is this a "solution looking for a problem"?
5. Could the same value be achieved with a simpler approach?

### 3. Override UX → `--gate necessity=false`

**Decision:** Standard autonomy gate pattern. Override with `--gate necessity=false`.

**Evidence:**
- Matches existing gate override pattern in /cortex-spec (same as `--gate contract_approval=false`)
- No new UX surface needed
- In `full-auto` preset, the gate is disabled (same as critical_uncertainty and evidence_backing)

### 4. Logging → decisions.md Autonomy Decisions section

**Decision:** Log the verdict in `docs/cortex/handoffs/decisions.md` under `## Autonomy Decisions`.

**Evidence:**
- Matches existing pattern for gate decisions (see current entries for slug_conflict, critical_uncertainty, etc.)
- Format: `- {timestamp} | gate: necessity | verdict: {BUILD|NARROW|DEFER|REJECT} | confidence: {N} | command: /cortex-spec`
- When auto-skipped (gate disabled): `- {timestamp} | gate: necessity | value: false (auto-skipped) | preset: {preset} | command: /cortex-spec`

### 5. False Positive Mitigation → Confidence threshold + override

**Decision:** Only block on REJECT or NARROW with confidence >= 0.7. Below 0.7, warn but don't block. DEFER always blocks (it's asking for more evidence, not making a judgment call).

**Evidence:**
- All 4 test cases produced confidence 0.85-0.92 — well above 0.7
- A low-confidence REJECT (e.g., 0.5) is the gate saying "I'm not sure this should be rejected" — that's a warning, not a block
- Override is always available via `--gate necessity=false`

## Integration Design

### Where it fits in /cortex-spec Phase 1

Current Phase 1 gate order:
1. Check active slug
2. Check clarify brief exists
3. Check complexity
4. Check research dossier exists
5. Read all research dossiers
6. Read clarify brief
7. Gate: reclarify (mandatory)
8. Gate: critical_uncertainty (autonomy-conditional)
9. Gate: evidence_backing (autonomy-conditional)

**Add as step 9.5 (after evidence_backing, before Phase 1b coherence check):**

```
9.5. Gate: necessity (autonomy-conditional)
     If gates.necessity is false: skip, log auto-skip to decisions.md
     If gates.necessity is true:
       - Build prompt from clarify brief + research dossiers + key context
       - Call Haiku for verdict
       - If REJECT (confidence >= 0.7): BLOCK
       - If NARROW (confidence >= 0.7): BLOCK with narrowing suggestion
       - If DEFER: BLOCK (always — asking for more evidence)
       - If BUILD: proceed
       - If any verdict with confidence < 0.7: WARN but proceed
       - Log verdict to decisions.md
```

### Gate configuration

```json
{
  "necessity": {
    "supervised": true,
    "gates-only": true,
    "full-auto": false
  }
}
```

Disabled in full-auto (same pattern as critical_uncertainty and evidence_backing).

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Implementation | Inline in /cortex-spec | Separate script / critic extension | Same context already has clarify + research loaded |
| Verdict method | LLM judgment | Rule-based heuristics | "Solution looking for a problem" can't be caught by rules |
| Model | Haiku 4.5 | Sonnet/Opus | Haiku is accurate enough (4/4 correct), cheaper, faster |
| Block threshold | confidence >= 0.7 | Fixed block/pass | Low-confidence verdicts shouldn't block |
| Override | --gate necessity=false | No override | Must be overridable — false positives are possible |
| Log location | decisions.md | New artifact | Matches existing gate logging pattern |
