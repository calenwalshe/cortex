# Clarify Brief: report-clarity

**Slug:** report-clarity
**Timestamp:** 20260412T060000Z
**Status:** draft
**Complexity:** standard

---

## Idea

The output format of cortex skills (research dossiers, slug summaries, status reports) is too technical and jargon-heavy — when the owner is multi-tasking and comes back to a session, it's hard to quickly understand what happened, what was found, and what's next; want clearer, more human-readable reporting that surfaces the "so what" without requiring the owner to parse walls of structured text.

---

## Goal

Cortex skill outputs communicate with extreme clarity — no jargon, no extraneous file references, no structural padding — so a returning multitasker understands what happened, what was found, and what's needed in under 30 seconds, without any prior context.

---

## Non-Goals

- Not changing contract.md, clarify briefs, or state.json — those are for skills and scripts to consume
- spec.md IS in scope for a human-readable reformat — the spec is the owner's primary approval surface and currently reads like AI output
- Not removing detail or depth from research dossiers — detail should remain accessible, just not forced on the reader before the summary
- Not redesigning all 16 skills from scratch — focus on the highest-traffic human-facing surfaces
- Not adding a separate "report" command — the improvement is inline in existing skill outputs
- Not changing the HITL report template structure — improving how consistently it's applied and how it's populated

---

## Constraints

- [owner-intent] No code without contract. Production code must not be written before a contract is approved.
- [owner-intent] Disk is truth. All state lives in repo artifacts. Any feature that stores state only in memory is a bug.
- [owner-intent] Low ceremony — changes must not add >15 minutes wall time overhead to standard slugs.
- Changes to skill output must be backward compatible — the same skill can produce the new format without breaking existing downstream artifact parsing.
- Scope to 3-4 highest-impact surfaces rather than attempting to reformat all skill output at once.
- **Extreme clarity over completeness** — if a piece of information doesn't help the owner make a decision or take an action right now, it does not belong in the summary layer. Omit rather than hedge.
- **No extraneous references** — file paths, slug names, timestamps, and artifact links should not appear in the human-facing summary layer unless the owner needs to act on them directly. They belong in the detail layer only.
- **Context of the medium matters** — outputs appear in a Claude Code terminal session. The owner may be switching between this and other work. The format must work for someone with zero working memory of the prior session.

---

## Assumptions

- The owner (single user) is the primary consumer of skill output — outputs are not shared with a team.
- The highest-pain surfaces are: research dossiers (findings buried in structured text) and spec.md (written for AI consumption, not owner comprehension). Owner confirmed these two are the primary pain points.
- The hitl-report template (`templates/cortex/hitl-report.md`) exists but is either not applied consistently or not populated in a way that surfaces the "so what" prominently enough.
- The problem is information hierarchy, not information volume — the owner wants the detail, just not first.
- A "returning after context loss" owner is the primary persona: they need the bottom line, not the step-by-step.
