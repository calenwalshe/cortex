# Clarify Brief: clarify-research-loop

**Slug:** clarify-research-loop
**Timestamp:** 20260411T234737Z
**Status:** draft
**Complexity:** standard

---

## Idea

iterative clarify-research convergence loop — current Cortex flow is one-shot clarify→research→spec with no mechanism to loop back when research reshapes the problem framing; want a formal convergence gate that re-enters clarify if research invalidates the brief, with a stopping criterion to avoid infinite refinement

---

## Goal

Cortex pipeline can iterate between clarify and research until the problem frame is stable enough to spec, with an explicit, bounded stopping criterion that prevents infinite refinement and produces an auditable trail of what reframings occurred and why.

---

## Non-Goals

- Not changing how /cortex-spec produces specs once the brief is stable
- Not replacing /cortex-research's existing concept/implementation/evals phase structure
- Not adding LLM-judged "is this brief good enough" gates (subjective, sycophancy risk per owner-intent)
- Not building a generic iterative agent loop — scope is specifically clarify↔research convergence
- Not retroactively re-running already-shipped slugs through the new loop

---

## Constraints

- [owner-intent] No code without contract. Production code must not be written before a contract is approved.
- [owner-intent] Validators must run. No slug closes without validators passing.
- [owner-intent] Disk is truth. Loop state must persist as repo artifacts, not chat context.
- [owner-intent] GSD owns execution. Cortex does not write to .planning/ except via /cortex-bridge.
- [owner-intent] No sycophantic evals. Convergence criteria must test real reframing signals, not surface "looks fine" compliance.
- Stopping criterion must be deterministic and auditable — a human reading decisions.md must be able to tell why iteration N was the last
- Must not break existing one-shot flow for trivial slugs that don't need iteration
- Must integrate with the existing 5-type question taxonomy (factual/landscape/mechanism/comparison/codebase) rather than introducing a parallel classification

---

## Assumptions

- The current pain is real and observable — research dossiers have surfaced reframings that should have looped back but didn't, producing specs that drifted from intent
- Most slugs converge in 1 pass (no loop needed); only some subset benefits from iteration — so the loop must be opt-in or auto-detected, not mandatory
- A clarify brief is a small enough artifact that re-writing it is cheap relative to the cost of a wrong spec
- Question-level state (which open questions got answered, which spawned new ones) is the right granularity for tracking convergence
- The 5-type question taxonomy is stable and can be reused for convergence signals

---

## Open Questions

- Where in the current Cortex flow does research feedback get lost — is it that /cortex-spec runs unconditionally after research, or that /cortex-research has no "should we re-clarify" output signal?
- What signals from a research dossier should trigger a re-clarify (e.g., invalidated assumption, new constraint discovered, scope inversion)?
- How do other spec-driven workflows (e.g., RFC processes, design doc loops, agile spike→story refinement) handle convergence between investigation and specification?
- What stopping criteria do iterative refinement systems use to avoid infinite loops (max iterations, delta threshold, human override, confidence score)?
- Should the convergence gate live as a new skill (/cortex-converge), as a phase inside /cortex-research, or as a check inside /cortex-spec that can route backward?
- Does the current cortex-research SKILL emit any structured "reframe needed" signal in its dossier output, or is the dossier always treated as terminal input to spec?
