# Clarify Brief: llm-judge-calibration

**Slug:** llm-judge-calibration
**Timestamp:** 20260404T003500Z
**Status:** draft
**Complexity:** complex

---

## Idea

Add LLM-based automated judgment scoring to Cortex contracts so that `[judgment]` validators — which currently require human review — can be scored by an LLM judge against rubrics. Human samples and corrects disagreements. Corrections become few-shot examples that improve the judge over time (calibration loop). Based on pattern #15 from pattern-harvest research — LangSmith Align Evals pattern. Goal: reduce the human bottleneck on ux_taste_eval and other judgment gates while maintaining quality through calibration.

---

## Goal

Any Cortex contract `[judgment]` validator can optionally be scored by an LLM judge using a rubric, producing a pass/fail/flag verdict with confidence score — and human corrections to judge outputs feed back as few-shot calibration examples, so the judge improves over time without retraining.

---

## Non-Goals

- Not replacing human judgment entirely (humans remain the final authority on flagged or low-confidence scores)
- Not building a general-purpose eval framework (this is scoped to Cortex contract validators)
- Not fine-tuning or training models (few-shot calibration only, no gradient updates)
- Not scoring `[external]` validators (those are deterministic and don't need judgment)
- Not building a UI for calibration review (CLI and file-based workflow)
- Not integrating with external eval platforms (LangSmith, Braintrust, etc.)

---

## Constraints

- Must work with locally available LLMs (ollama) and/or Claude API — no vendor lock-in to a single provider
- Rubrics must be defined per-validator in the contract or in a separate rubric file — not hardcoded
- Calibration examples must be stored as plain files (JSONL) in `.cortex/calibration/` — no database
- Judge latency budget: <30 seconds per validator (LLM calls are slower than code checks, but shouldn't block for minutes)
- Must not modify existing contract format — adds optional fields, doesn't change required ones
- Calibration data must be portable across projects (global `~/.cortex/calibration/` for cross-project learning)

---

## Assumptions

- ollama with a capable model (phi3:3.8b or larger) can produce useful judgment scores against structured rubrics
- Claude API is available for higher-quality judging when needed (fallback or primary depending on config)
- 10-20 calibration examples are sufficient to meaningfully improve judge agreement with human reviewers
- A simple rubric format (criteria + scoring levels) is sufficient — no need for complex rubric DSLs
- The existing `[judgment]` validator annotation in contracts provides enough structure to attach rubrics

---

## Open Questions

- **Rubric format:** What structure for rubrics? YAML inline in contract? Separate `.rubric.md` files? JSON schema? Need to balance readability with machine-parseability.
- **Judge model selection:** Should the judge model be configurable per-project? Per-validator? What's the quality/cost tradeoff between ollama phi3 and Claude API?
- **Calibration storage:** Per-project `.cortex/calibration/` or global `~/.cortex/calibration/`? Cross-project calibration data could be valuable but risks domain leakage.
- **Confidence thresholds:** At what confidence level does the judge auto-pass vs flag for human review? Fixed threshold or adaptive?
- **Integration point:** Does the judge run as part of `gate-check`? As a separate `/cortex-judge` command? Both?
- **Human correction workflow:** How does the human correct a judge output? Edit a file? CLI command? What's the minimal-friction path?
