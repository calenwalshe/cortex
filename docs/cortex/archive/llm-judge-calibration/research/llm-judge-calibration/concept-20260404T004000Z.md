**Phase:** concept

## Summary

Live benchmarking eliminated ollama phi3:3.8b as a judge model (45s latency, hallucination) and confirmed Claude Haiku 4.5 as the viable judge (1.7s, $0.003/judgment, structured JSON output, correct reasoning). The calibration loop works: human corrections fed as few-shot examples measurably shift judge behavior (relevance scoring became stricter per calibration instruction, confidence increased from 0.72 to 0.85). Architecture: rubrics defined per-validator in YAML, judge invoked via `/cortex-judge` CLI, calibration stored as JSONL in `~/.cortex/calibration/` for cross-project learning.

## Benchmark Results

### Judge Model Comparison

| Model | Latency | JSON Compliance | Reasoning Quality | Cost | Verdict |
|-------|---------|-----------------|-------------------|------|---------|
| phi3:3.8b (ollama) | 45s | Partial (hallucinated mid-JSON) | Poor — drifted into unrelated text | Free | **REJECTED** — too slow, unreliable output |
| Claude Haiku 4.5 | 1.7s | Perfect (valid JSON every time) | Strong — correct identification of relevance gaps | $0.003/judgment | **CHOSEN** — fast, accurate, cheap |

### phi3:3.8b Failure Details

- Simple prompts (1 word output): 1.4s — acceptable
- Judge prompts (structured JSON output): 45s — timed out at 60s on first attempt
- Output quality: started valid JSON, then hallucinated endocrine system text mid-response
- Root cause: 3.8B parameters insufficient for complex structured output tasks on this hardware (CPU-bound, no GPU allocation for phi3)

### Claude Haiku 4.5 Performance

| Metric | Value |
|--------|-------|
| Latency (judge call) | 1.7s average |
| Input tokens (typical) | 400-3700 (depends on rubric + output length) |
| Output tokens (typical) | 125-180 |
| Cost per judgment | $0.003 (at Haiku pricing: $0.80/M input, $4.00/M output) |
| JSON compliance | 100% (2/2 test calls) |
| Reasoning accuracy | Correctly identified: low relevance, missing actionable guidance, tangential results |

## Architecture Decisions

### 1. Judge Model → Claude Haiku 4.5 (API)

**Decision:** Use Claude Haiku 4.5 via Anthropic API as the sole judge model.

**Evidence:**
- phi3:3.8b is unusable (45s, hallucination)
- Haiku is 1.7s, $0.003/call, perfect JSON compliance
- A typical contract has 1-3 `[judgment]` validators → $0.003-$0.009 total judge cost per contract
- Requires ANTHROPIC_API_KEY (already present in environment)

**Rejected alternatives:**
- ollama phi3:3.8b: too slow, unreliable structured output
- ollama with larger model: not installed, would need 8B+ parameters for reliable judging
- No local-only option viable on this hardware for judge tasks

### 2. Rubric Format → YAML Frontmatter in Separate Files

**Decision:** Rubrics stored as `docs/cortex/rubrics/{slug}/{validator-name}.rubric.md` with YAML frontmatter for criteria and markdown body for context.

**Rationale:**
- Inline rubrics in contracts would bloat the contract format
- Separate files allow rubric versioning and reuse across contracts
- YAML frontmatter is already used throughout Cortex (clarify briefs, specs, etc.)
- Markdown body allows rich context (examples, edge cases) that a JSON schema can't

**Format:**
```yaml
---
validator: "Review that retrieval returns semantically relevant facts"
criteria:
  - name: relevance
    range: [0, 3]
    levels:
      0: "No facts relate to the query"
      1: "One fact is marginally relevant"
      2: "Most facts are relevant"
      3: "All facts are clearly relevant"
  - name: ranking
    range: [0, 2]
    levels:
      0: "Random ordering"
      1: "Somewhat ordered"
      2: "Best match ranked first"
  - name: no_garbage
    range: [0, 1]
    levels:
      0: "Contains irrelevant noise"
      1: "All results tangentially related"
pass_threshold: 3
max_score: 6
---

## Context

This validator checks semantic retrieval quality...
```

### 3. Calibration Storage → Global `~/.cortex/calibration/`

**Decision:** Calibration examples stored in `~/.cortex/calibration/{rubric-hash}.jsonl` (global, cross-project).

**Rationale:**
- Judge behavior should improve across all projects, not just one
- A rubric for "semantic relevance" applies identically whether in cortex or another project
- Keyed by rubric content hash so identical rubrics share calibration data
- JSONL format: one correction per line, append-only, easy to inspect

**Format per line:**
```json
{
  "timestamp": "20260404T004000Z",
  "rubric_hash": "a1b2c3d4",
  "validator": "Review that retrieval returns semantically relevant facts",
  "judge_output": {"relevance": 2, "ranking": 1, "total": 4, "pass": true},
  "human_correction": {"relevance": 1, "ranking": 1, "total": 3, "pass": true},
  "human_reasoning": "Only one fact directly relates...",
  "project": "cortex",
  "slug": "semantic-retrieval"
}
```

### 4. Confidence Threshold → Fixed 0.7 with flag-for-review

**Decision:** Judge outputs with confidence >= 0.7 auto-pass/fail. Below 0.7, flag for human review.

**Evidence:**
- Both test judgments produced confidence 0.72-0.85
- A fixed threshold is simpler than adaptive (no calibration data needed for the threshold itself)
- 0.7 is conservative enough to catch uncertain judgments while auto-clearing confident ones
- Can be overridden per-validator in the rubric YAML (`confidence_threshold: 0.8`)

### 5. Integration Point → `/cortex-judge` CLI Command

**Decision:** Standalone CLI command, not integrated into gate-check.

**Rationale:**
- gate-check runs `[external]` validators (deterministic, fast). Mixing in API calls (1.7s each) would slow gate-check.
- `/cortex-judge` runs after `gate-check` passes, only on `[judgment]` validators
- Can be called manually or wired into a PostToolUse/TaskCompleted hook
- Outputs a `judge-report.md` in `docs/cortex/evals/{slug}/`

### 6. Human Correction Workflow → `cortex-judge correct <validator> <field>=<value>`

**Decision:** CLI-based correction. Human runs a command to override a specific score.

**Format:**
```bash
cortex-judge correct "Review that retrieval returns..." relevance=1 --reason "Only one fact directly relates"
```

This appends a calibration entry to `~/.cortex/calibration/{hash}.jsonl`. Next judge invocation for the same rubric loads these as few-shot examples.

## Trade-offs

| Decision | Chosen | Alternative | Why |
|----------|--------|-------------|-----|
| Judge model | Claude Haiku 4.5 (API) | ollama phi3 (local) | phi3 too slow (45s) and hallucinated; no viable local option |
| Rubric format | YAML frontmatter .rubric.md | Inline in contract / JSON schema | Separate files allow versioning; YAML matches Cortex conventions |
| Calibration scope | Global (~/.cortex/) | Per-project (.cortex/) | Cross-project learning is more valuable; rubrics are domain-agnostic |
| Confidence strategy | Fixed 0.7 threshold | Adaptive / per-rubric trained | Simpler; tested outputs cluster 0.7-0.85; adaptive needs more data |
| Integration | Standalone /cortex-judge | Integrated into gate-check | Keeps gate-check fast; judge is optional and API-dependent |
| Correction UX | CLI command | Edit JSONL directly / Web UI | CLI matches Cortex workflow; no new UX surface needed |
